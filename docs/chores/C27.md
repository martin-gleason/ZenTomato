# C27 — the standing documents, after the rescope

**Owner: the agent.** No user-visible change. A defect fix, not a feature.

**No gate.** `conventions.md` — *"Defect fixes proceed without a gate… the distinction
is whether the app is failing to do what the contract already says."* Every line
below contradicts ratified text, so this is a correction rather than a proposal.

## What was wrong

`docs/specs/zenpom-v1.5.md` was ratified **2026-09-09**. For two days the standing
documents went on describing the milestone it replaced.

| File | Line | Said | Ratified text |
|---|---|---|---|
| `CLAUDE.md` | 3 | `SPEC.md` is "the contract" | three ratified documents; v0.1 wins on conflict |
| `CLAUDE.md` | 10 | "Scope is `SPEC.md` F1–F6 and nothing else" | v1.5's eleven items; the polish/platform fence |
| `CLAUDE.md` | 15 | "Hard stop September 13, 2026" | **`D35`: v1.5 ends at TestFlight** |
| `CLAUDE.md` | 19 | "watchOS 26.0 **if F7 lands**" | `F7` landed; `ZenTomatoWatch/` is in the tree |
| `CLAUDE.md` | 27 | gate re-reads `SPEC.md` | both specs, `definitions.md`, the register |
| `CLAUDE.md` | 29 | outstanding items live in `SPEC.md` | `docs/reviews/OPEN.md`, `00-register.md` |
| `docs/conventions-local.md` | 7 | "thirteen days from a hard stop" | the date was lifted |
| `.claude/agents/adversarial-reviewer.md` | 16 | "widgets, themes … any of these is a FAIL" | `F12` and `F17` are ratified v1.5 items |

**The last one is the only one that could have done damage.** The other seven
misinform a reader. That one instructs the mandatory reviewer to fail ratified work
as a scope violation, at the end of every feature and the start of every session —
and `F12` Themes is item 3 on the list.

**The September 13 date was anchored to an exam that was cancelled.** It was
replaced by a condition, not another date, precisely so it could not expire again.

## What was done

The literal corrections, against the ratified text. **Nothing here is new process** —
the adversarial review found two changes that were, and they have been withdrawn:

1. **The gate's re-read list** was rewritten to add the register and an instruction
   about `CLAUDE.md`'s own staleness. That is a new decision procedure, not a
   correction, and `conventions.md` says *"everything else waits for a yes."*
   **Reverted** to a plain pointer correction: the three ratified documents, named,
   because there are now three and the line named one.
2. **The reviewer brief's `Read first` expansion and precedence clause** — *where this
   file and a ratified document disagree, this file is the defect* — was likewise new
   process, and the adversarial review was right to refuse it as ungated.
   **RATIFIED BY THE OWNER 2026-09-11**, in their words: *"I approve of the Read First
   expansion — this needs be a part of the turing review and is being worked on in that
   space."* It stays, and the durable form is being built upstream rather than here.

   **The gate was real even though the answer was yes.** The review's objection was not
   that the change was wrong — it is being promoted upstream, so it was right — but that
   **the reviewee had rewritten the reviewer's instructions with no owner yes.** That is
   the one edit that can never be self-served, and the fact that this one turned out to
   be correct is exactly why the shape matters: a self-served edit that happens to be
   right is indistinguishable, at the moment it is made, from one that is not.

**The scope line in the brief stays**, because it is a literal correction: it named
`F12` and `F17` as automatic failures while both are ratified v1.5 items.

**The compounding problem, stated plainly:** the reviewee rewrote the reviewer's
instructions with no owner yes. The direction was right — the review that caught this
benefited from the corrected scope line — but the governance shape was wrong, and a
reviewee editing its own reviewer is the one edit that should never be self-served.

## Why no check was added

A checker was drafted — *fail if a standing document names a stop condition the
specs do not* — and **measured before it was written down**, per `conventions.md`'s rule
that a mutation is named and *run* before the row is written. (That rule carries an
upstream decision number, deliberately not cited here: `DeltaIntegrityTests` walks this
file for `D<n>` citations and resolves them against **ZenPom's** register, where that
number is undefined. Citing another project's register in this one is a broken citation,
and the fence caught it.)

Over the 18 governed projects:

| Version | Hits | True | False | Against 10 invented scope facts |
|---|---|---|---|---|
| broad | 26 | 3 | 23 | — |
| narrowed | 3 | 3 | 0 | **0 of 10** |

**Broad is 88% noise; narrowed is a tautology.** The noise is not incidental — it is
the conventions' own vocabulary. `"primary ID in scope"` is the **conventional-commit
scope field** and appears verbatim in eight projects. `"deadline veto"` is the
ratified 🎓 override. One hit was a sentence in this chore's own fix describing the
stale deadline — mention-versus-use, the disease that already forced a four-file
allowlist onto `check-licence-wording.sh`.

Narrowing to kill the noise produced a pattern that catches the three lines already
read and **none of ten milestone-scoped facts invented for the mutation**. That is
`conventions.md`'s tautology rule exactly: *a fixture that satisfies both the right
and the wrong implementation distinguishes nothing.*

**So no fence ships here.** A second guard with `check-licence-wording.sh`'s weakness
and none of its precision is worse than no guard.

**The probes are committed, because a negative mutation result is the one that most
needs its artifact** — it is the argument for shipping nothing, and a precise table
with nothing behind it reads as measured when it is not. Reproducible:

```
scripts/probes/standing-doc-detector-v1.py    → OUTPUT-v1.txt          (26 hits)
scripts/probes/standing-doc-detector-v2.py    → OUTPUT-v2-mutations.txt (0 of 10)
scripts/probes/standing-doc-mutations.md      — the ten invented scope facts
```

They are probes, not gates: nothing runs them, they are not in `make checks`, and they
exist so a second reader can reproduce the numbers above rather than take them.

## What the sweep found, and why the answer is small

The defect class is not *prose goes stale*. It is **a ratification is a gate with no
consequent action** — the owner's framing. Ratifying v1.5 should have fired a sweep;
it fired nothing.

Swept the tree for scope assertions (`F1–F6`, `Phase 2`, `hard stop`,
`September 13`, `out of scope`): **~65 hits, in three groups.**

| Group | n | Actionable |
|---|---|---|
| Historical records — `00-deltas.md`, plans, handoffs, reviews | ~45 | **No.** A plan saying *"twenty days to the hard stop"* is correct as a record. These are append-only baselines; a sweep that flags them is 70% noise on day one. |
| Executable fences encoding the old scope | 2 | **No — already covered.** |
| Live standing documents | 5 | **Yes.** This chore. |

**Group 2 is the finding.** `PolishFenceTests.theTokenLayerDoesNotGrow` pins
`ColorRole` at exactly 20 cases, reasoned as *"`SPEC.md` puts themes out of scope"*,
and `StatsFenceTests` fails the build on gamification vocabulary — with `F12` and
`F16` both ratified. These look like live landmines in the path of the next two
features. **They are not.** `F12.md:100` cites that test by name and designs themes
as a swap behind existing roles; `F16.md:8` logs the delta it owes. Both plans found
their own fence, at the gate, by hand.

**So the per-feature gate already sweeps — narrowly and deeply.** You cannot write
`F12.md` without reading the token layer. Every file a feature touches is re-read by
that feature's plan.

**The files that went stale are precisely the files no feature plan owns.** No plan
is ever written *about* `CLAUDE.md`, `conventions-local.md`, or the reviewer brief.
They are read by every feature and owned by none, so the per-feature gate sweeps past
them forever. That is not a lapse in vigilance; it is a structural hole, and all five
stale lines sat inside it.

The correct sweep is therefore **not** "enumerate every file that asserts scope" —
that is all three groups, and two are already covered. It is: **on a scope event,
re-read the standing documents, because nothing else ever will.** Three or four files
here. No pattern, no allowlist, no judgement about what a sentence means.

**That list already exists in code.** `turing-review`'s `check_instructions.py:62`
declares its surface — `CLAUDE.md`, `conventions.md`, `docs/conventions-local.md`,
`.claude/agents`, `.claude/skills`, `skills` — derived from a different argument
(*files read into context and obeyed*) and landing on the same enumeration. Measured
across the 18 governed projects the set is **3 to 6 files, and every project carries
exactly one agent brief**. The sweep does not degrade on the project that has more of
them, because no project does.

## Found while writing this: the register check does not read the register

Adding `C27`'s row surfaced a malformed table in `docs/plans/00-register.md`. The
**Chores** table's header declares six columns; `C26`'s row carried seven. In a
strict renderer the chore table stops being a table at that row — the exact failure
`check-open-register.sh` was built for, after `O16` lost a cell and hid six owner
items from the reader the owner actually scans.

**The check could not have caught it.** `scripts/check-open-register.sh:32` reads a
one-element list:

```sh
for file in docs/reviews/OPEN.md; do
```

`docs/plans/00-register.md` is not scanned, though `conventions.md` names *it* as the
register — *"`D` · `RR` · `O` · `H` · `M` live in `docs/plans/00-register.md`"* — and
the script's own header says *"The register IS the mechanism for not losing things."*
**The hook's surface is narrower than its stated purpose, and a malformed row was
sitting in the half it does not read.**

### Two wrong fixes preceded the right one, and the reason is this chore's own subject

**The first fix folded `@chores` into the `Why` text.** Wrong: the file's own header
says `P`, `Status` and `Mode` are the owner's and are carried through, so a hand-merge
would be clobbered.

**The second fix declared a `Mode` column in the chore header**, on the stated grounds
that *"this is what the generator already emits."* **That claim was false and was never
run.** `scripts/extract_zenpom.py:472-475` emits chores from a hard-coded five-column
list and carries a comment saying exactly why:

```python
# No Mode column here: ZenPom records no mode for a chore, and emitting four
# cells under a five-column header is what sent a td: id under `Mode`.
L += table(c, ["id", "title", "p", "status", "why"],
           ["ID", "Title", "P", "Status", "Why"])
```

So the diagnosis was **inverted**. The header was correct all along; `C26`'s row was a
hand edit — `git log -S'@chores'` returns `5e0305a`, `C26`'s own commit — and at
`HEAD~1` the header and all twelve other chore rows carry six cells while `C26` alone
carries seven. Declaring the column would have propagated an empty cell to twelve clean
rows and had the whole column deleted on the next run, taking `C26`'s `@chores` with it,
silently, because the merge parser reads by header *name* and `table()` then never emits
what it parsed.

**The right fix is one line: delete `C26`'s stray seventh cell.** Done here, with the
header untouched.

**This is the defect this chore is about, committed by this chore.** A claim about what
another system does, written in a confident register, never executed —
`conventions.md`: *"A decision about what another system can do is not ratifiable until
something has run… the evidence is the observable end state, not the configuration
field."* The file's own line 3 says it is generated. Running the generator was one
command and would have settled it in seconds; it was not run until the adversarial
reviewer demanded it. Recorded rather than quietly corrected, because the near-identical
failure is what the rest of this document is about.

**Widening the check to both files is not done here** and is not free: `00-register.md`
is generated, so the fix for a malformed row there is a generator fix, and this chore
has no gate to change generator behaviour. Recorded rather than absorbed.
