# C9 — TestFlight runbook

**Owner: both.** The agent can write the runbook and prepare the build; only the owner can
hold the Apple Developer account, accept agreements, and press submit.

**In progress.** Agreed 2026-08-24. First upload attempted 2026-08-25 and blocked before it
began — see **Step 0** below, which is the only thing standing between this project and a
TestFlight build.

## What this is, and what it is not

A **repeatable procedure** for getting a build onto a tester's phone, written the way this
project writes device checks: numbered, with the failure modes named, and with the thing that
proves each step worked.

It is not App Store submission. That is `C10`'s decision first and a separate chore after.

**Homebrew is not a route and should not appear in it.** Casks install macOS software; there
is no mechanism for putting an iOS app on a phone through Homebrew. It was on the original
list for tomorrow and is struck here so nobody spends a morning on it.

## What it has to cover

- **The prerequisites that are already known to bite.** An explicit App ID rather than the
  team wildcard (`O14` — still open, and TestFlight will want it for MusicKit), the watch
  app's own App ID, and the fact that `install-device.sh` stamps a timestamp build number that
  App Store Connect will reject a *duplicate* of but not a *decreasing* one.
- **Archive and upload**, from the command line if possible, because `project.yml` says no
  Xcode GUI is ever required for building and it would be good to keep that true.
- **Export compliance**, which the app already answers with
  `ITSAppUsesNonExemptEncryption: false`.
- **What a tester actually sees on first launch**, which is a screen asking for a Todoist
  personal API token — and whether that is acceptable for somebody who is not the owner. This
  is the one that may need a decision rather than a step.
- **The watch app**, which reaches a tester's wrist by the same route it reached the owner's
  and has already produced four silent failures.

## Step 0 — the app record must exist first, and its name is the hard part

**This is where the first real attempt died, on 2026-08-25.** Xcode's Distribute assistant ran
correctly, found no app record, offered to create one, and App Store Connect refused:

```
POST /v1/apps → 409
ENTITY_ERROR.ATTRIBUTE.INVALID.DUPLICATE.DIFFERENT_ACCOUNT
"The App Name you entered is already being used. If you have trademark rights
 to this name and would like it released for your use, submit a claim."
```

The assistant was then cancelled, because there was nowhere for the build to go.

**Nothing was wrong with the build.** `IDEDistribution.critical.log` is zero bytes and the
portal log is clean. The archive, the signing and the certificates were all fine — the upload
never started.

### The distinction that costs an hour if you miss it

Three names are in play and only one was rejected:

| | Value | Unique across | Status |
|---|---|---|---|
| Bundle ID | `com.martingleason.ZenTomato` | your team | fine |
| **App Store name** | `ZenTomato` | **every account on the App Store** | **rejected** |
| Home-screen name (`CFBundleDisplayName`) | `ZenTomato` | nothing | fine |

So this costs **nothing in code**: no rebuild, no re-archive, no bundle-ID change, and the home
screen can go on saying ZenTomato. Only the store listing needs a different name.

### The step

1. App Store Connect → **Apps** → **+** → **New App**
2. Platform **iOS**; Bundle ID `com.martingleason.ZenTomato` from the dropdown
3. **Name** — must be globally unique. A qualified form usually clears where a bare word does
   not: *ZenTomato Focus*, *ZenTomato Pomodoro*, *ZenTomato Timer*.
4. **SKU** — `com.martingleason.ZenTomato` is fine; it is private to the account
5. Primary language English (U.S.)

**Proof the step worked:** re-running Distribute reaches *Upload* instead of offering to create
an app.

**Do not choose the name in a hurry.** It is effectively permanent once builds ship under it,
and it is the name a public GPL-licensed repository will be associated with — which makes it
`C10`'s business as much as this chore's. Tracked as `O19`.

## Verified: archive and upload from the command line

`C12` established that the whole binary can be produced without the Xcode GUI, which keeps
`project.yml`'s promise true. These commands were run and produced a signed 2.0 MB IPA
containing the app, the watch app and the Live Activity widget:

```sh
xcodebuild archive -project ZenTomato.xcodeproj -scheme ZenTomato \
  -configuration Release -destination 'generic/platform=iOS' \
  -archivePath build/ZenTomato.xcarchive -allowProvisioningUpdates

xcodebuild -exportArchive -archivePath build/ZenTomato.xcarchive \
  -exportPath build/export -exportOptionsPlist ExportOptions.plist \
  -allowProvisioningUpdates
```

with `ExportOptions.plist` naming `method: app-store-connect`, `teamID: KH6NBQRZBY`, and
`signingStyle: automatic`. Setting `destination: upload` instead of `export` uploads directly —
**but only once Step 0 is done**, since it fails in exactly the same place.

**Two prerequisites from the list above are now confirmed satisfied rather than assumed:**

- **The explicit App ID exists and works.** All three components carry their own Store
  provisioning profiles: `com.martingleason.ZenTomato`, `.Activity`, `.watchkitapp`.
- **Export compliance is answered in the binary** — `ITSAppUsesNonExemptEncryption: false`, so
  TestFlight will not ask on every upload.

**Build numbers.** The archive is `0.9.0 (1)`. App Store Connect rejects a *repeated* build
number and accepts anything higher, so the number must rise on every upload. Xcode's assistant
was set to `manageAppVersionAndBuildNumber: true`, which does this for you; a command-line
upload does not, and `CURRENT_PROJECT_VERSION` in `project.yml` has to be bumped by hand.

## Open question, and it is not small

**Who are the testers?** `SPEC.md` has no user other than the owner, and the app has no
onboarding beyond a token field. A beta with strangers in it is a different product question
from a beta with two friends in it, and the answer changes what the runbook has to say about
first launch.
