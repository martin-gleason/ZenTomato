# C10 — GPL-3.0 and the App Store: a decision, not a task

**Owner: the owner.** It is a licensing decision about their own work.

**Not started.** Agreed 2026-08-24 for the following day. **Blocks App Store distribution and
should be settled before any submission work begins**, because the answer may be that there is
none.

## The conflict, stated plainly

`SPEC.md` line 4: **GPL-3.0-or-later (copyleft, open source). Public GitHub repo.**

The Free Software Foundation's position is that the App Store's terms are **incompatible with
GPLv3**. The App Store imposes usage rules — device limits, DRM — on everyone who downloads an
app, and GPLv3 forbids adding restrictions beyond the licence. Apps have been pulled over this
before; VLC is the well-known case.

**This is not a technicality that goes away by ignoring it.** It is a conflict between two
things the project has already committed to.

## What tomorrow has to produce

A ruling, and it belongs in `SPEC.md` rather than in a plan. The options, so far as they are
known before research:

1. **Keep GPL-3.0, do not ship to the App Store.** TestFlight for a private group, or source
   distribution and let people build it. Costs reach; costs nothing else. The spec already
   says the hard stop abandons unmerged work cleanly, and "not on the App Store" is a
   defensible end state for a personal tool.
2. **Relicense.** The owner holds the copyright — the agent's contributions are work made for
   them — so this is theirs to do. A permissive licence (MIT, Apache-2.0) removes the conflict
   entirely. It also gives up the copyleft the spec chose on purpose, and that reason should
   be re-read before it is discarded.
3. **Dual licence.** GPL-3.0 for the repository, a separate grant for the App Store binary.
   Legitimate and common, and it needs the owner to be comfortable being the licensor of both.
4. **GPL-2.0-or-later or LGPL.** Sometimes claimed to be less restrictive here. **Verify
   rather than assume** — the anti-tivoisation clause is a GPLv3 addition, but the FSF's
   objection to the App Store's usage rules is not solely about that clause.

## What the agent should do first, tomorrow

**Research before recommending.** The last two times a decision was put to the owner without
investigating first, the investigation collapsed the question — the Todoist project attribution
needed no schema change, and the time-zone edge case turned out to be one other systems
disagree about. This one has the same shape: a well-documented question with real precedent, on
which an unresearched recommendation would be worth very little.

Sources worth reading rather than recalling: the FSF's own statements on the App Store, the
VLC removal and what actually caused it, and how currently-shipping GPL-licensed iOS apps
handle it — if any do.
