# C12 — the configuration that ships is now built by the gate

**Owner:** the agent. **No user-visible change.**

Asked for a pass to confirm the codebase was "working well enough for a binary
package." Rather than reason about it, the pass built one.

## The headline: a binary package exists and is sound

A full App Store archive and export were run for the first time in this project's
life:

- **`ZenTomato.ipa`, 2.0 MB**, signed **Apple Distribution: Martin Gleason (KH6NBQRZBY)**
- All three components present and separately Store-provisioned — the app, the
  **watch app** (`Watch/ZenTomatoWatch.app`), and the **Live Activity widget**
  (`PlugIns/ZenTomatoActivity.appex`)
- `NSAppleMusicUsageDescription` present — its absence is a launch-time crash the
  moment MusicKit authorization is requested
- `ITSAppUsesNonExemptEncryption = false`, so TestFlight will not ask on every
  upload
- `UIBackgroundModes: audio`, `NSSupportsLiveActivities`, `MinimumOSVersion 26.0`
- `Metadata.appintents` present in **both** the app and the widget, containing
  `DismissBlockIntent` — the AlarmKit stop button is genuinely wired, not just
  compiled

**Version is `0.9.0 (1)`.** Build number `1` is fine for a first upload and must
increase on every subsequent one; App Store Connect rejects a repeat.

## The finding: nothing had ever compiled Release

`make build`, `make test`, and every CI run since F1 compiled **Debug for the
simulator**. The binary a person installs is built with `-O` and whole-module
optimisation, and those are not the same compiler run.

The first Release build produced **two data-race warnings** — in a project whose
stated standard is `SWIFT_STRICT_CONCURRENCY: complete`. Both were SwiftUI
`Binding` setters handed a plain closure where the SDK wants
`@isolated(any) @Sendable`.

### And fixing them crashed the compiler

The precise annotation — `@MainActor (Bool) -> Void` — **crashed Swift 6.3.3**
while emitting IR for a reabstraction thunk under `-O`:

```
While emitting IR SIL function "@$sSbScA_pSgIeAghyg_SbIeAghn_TR"
Command SwiftCompile failed with a nonzero exit code
```

Debug compiles it without complaint. **A compiler crash that only the shipping
configuration can produce is exactly what a Debug-only gate cannot catch**, and
it would have been discovered by whoever first tried to ship.

### What was done instead

`@Sendable` on the closure properties through the chain — `MusicRow`,
`MusicPickerView`, `TimerScreen` — and `MainActor.assumeIsolated` at the one
place a main-actor method is called from one.

`assumeIsolated` rather than `Task { @MainActor in }` deliberately. SwiftUI calls
a `Binding` setter on the main actor, so it asserts something already true, and
traps loudly if that ever stops being true rather than racing quietly. The `Task`
form also compiles and defers the toggle by a run-loop turn — a switch that moves
one turn after the tap is the kind of lag `F7` spent a device session finding.

**The shipping archive now has zero warnings and zero errors.**

## The gate

`scripts/check-release-build.sh`, wired into `make ci` and into CI as its own
step. It compiles Release unsigned — CI holds no certificate and must still be
able to run it — and **fails on any warning whose path is inside this checkout.**
SDK warnings are excluded, because a gate nobody can satisfy is a gate somebody
deletes rather than meets.

**Mutation-verified (M20):** the original data-race warning was reintroduced and
the gate failed with the file and line. It is enforcement, not decoration.

## Open, and not fixed here

**No `PrivacyInfo.xcprivacy`.** Checked properly rather than assumed: no
required-reason API is used anywhere — the only `UserDefaults` in the tree is a
word inside a comment explaining why SwiftData was chosen instead — and the app
collects nothing and sends nothing outside Todoist and MusicKit. So a manifest is
**not** strictly required today.

It is still worth adding, because it makes "collects nothing" machine-readable
rather than a claim in a README, which is this project's whole disposition. It is
a small file and it is not this chore's scope. **Recorded as `O18`.**

**`LSApplicationCategoryType` is unset.** Set in App Store Connect at submission
rather than in the binary; noted so nobody hunts for it later.

**The IPA has not been uploaded or validated against App Store Connect.** That
needs an API key and is `C9`'s business, not this pass's. What is established is
that a signed, complete, correctly-configured binary can be produced from a clean
checkout.
