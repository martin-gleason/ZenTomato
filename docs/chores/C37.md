# C37 — generate `docs/reviews/OPEN.md` from the register

**Status:** closed 2026-09-24. **Owner:** agent. No user-visible change.
**Key:** the last step of the migration `D36` and `D37` began. After it, `OPEN.md` is not
authoritative; `docs/plans/00-register.md` is.

## What it is for

`docs/conventions-local.md` defines `OPEN.md` as *"every outstanding item from every review,
in one table"*, and the register holds the same items. Two documents, one intake path each,
is the failure `docs/conventions.md` names: *"a second document is a second intake path."*
`O44` measured what the second path had cost — 16 of `OPEN.md`'s 35 `O` ids and 83 lines of
prose existed nowhere else — and the owner ruled *"two files to maintain is exactly what I
think we need to avoid. Stick with register and regenerate open.md."*

## What was built

1. **`From` is a register column.** It existed only in `OPEN.md`, so generating without it
   would have dropped the provenance of 67 items. 57 came across from `OPEN.md`, 3 were
   derived, 7 were filled by hand; none is blank.
2. **Sixteen closed rows were transcribed into the register** before anything was generated —
   the half of `O44`'s loss the register could absorb, each marked `TRANSCRIBED FROM
   docs/reviews/OPEN.md 2026-09-24 by C37` and carrying `OPEN.md`'s own words, not a rewrite.
3. **`O48` was ruled and closed by the owner:** *language in `docs/conventions.md` is contract,
   not implementation.* The owner-fields overlay is now `### Decisions — owner fields` inside
   the `D` section, and both `gen_status.parse_tables` and `check_register_rows` treat a `###`
   as a section boundary. The wider ruling is recorded on the row: the reviewing agent should
   have held to `conventions.md` rather than proposing a reading of it.
4. **Two marker pairs in `OPEN.md`**, one per table. `splice_open()` replaces the rows between
   them and changes no line outside; the generator refuses to write if a pair is missing
   (`C37-M3`). The 83 prose lines sit outside the markers and are untouched.
5. **`scripts/open_backfill_diff.py`**, in `make checks` as `check-open-backfill`.

## The diff, which is the artefact this chore owed

The register row said it before the work started: **any row present before and absent after is
a backfill defect, not a row to accept.** So the diff is a check with an exit code, not a
paragraph:

```
open_backfill_diff.py: 71 rows before, 82 after, against 66232e8^
  kept verbatim ......... 67
  reworded, ruled in C37  4
  UNACCOUNTED FOR ....... 0
```

**It took three attempts to write, and the first two lied in opposite directions.** Recorded
because the failure is the one this project keeps paying for — an instrument that agrees with
whatever it is asked:

| attempt | what it reported | why it was wrong |
|---|---|---|
| id-level | zero loss | ids, not rows. `O23`/`O24`/`O25` each had two rows before and one after. |
| shingled per row | 4 lost, then 39 | phrases spanning the `CLOSED …` clause as it moved out of the title cell. A boundary that moved is not text that went missing. |
| shingled per cell | 16 lost | the seam is *inside* one before-cell — title and closure marker shared it — and no per-cell window sees across a split the generator made. |
| **aligned per row** | **0 unaccounted for** | an in-order word alignment against the row's counterpart sees both. |

**The four `reworded` rows are a human ruling and the script says so.** `~~O3~~`, `~~O4~~`,
`O46` and `O48` state the same substance in the register's own words; the lost runs are printed
in full so the ruling can be checked rather than trusted. `~~O4~~`'s is narration about
`OPEN.md` being stale against the register, which generation makes moot.

## Four defects the diff found and the gates did not

1. **`open_row` clipped the Why at 900 characters and the title at 200.** This is `C29` — 15
   register rows cut at ~110 characters by a truncating extractor — rebuilt by me *inside the
   generator that replaced it*. `O47` went from 3111 characters to 910. `OPEN.md` is the prose
   record, not a chart; it truncates nothing. `C37-M1`.
2. **`OPEN.md` carried two `O23`s, two `O24`s and two `O25`s**, so the register — one row per
   id — could keep only one of each. **Four rows were orphaned, not three:** the register's
   `O24` had merged both titles into a single row *and its Why was empty*, the only empty Why
   in 298 rows, which the validator passed because `R4` checks `Status`. All four are recovered
   verbatim as `C-7`–`C-10` in `OPEN.md`'s hand-maintained `## Closed` table. They are not
   renumbered: renumbering a collision needs the owner's ruling, `C33` said so, and
   `## Defect — reused IDs` still holds the question.
3. **`O23`'s `From` was `F2c`** — taken from the struck bell row it collided with. The
   progress-bar item came from `F5`.
4. **`gen_status.py --check` guarded three artefacts and its success line named two**, which
   is how a reader concludes a generated file is unguarded when it is guarded.

## The harness defect `C37-M5` found, which is worth more than the mutation

`C37-M5` was applied and **the suite reported nothing**: it printed its banner, exited 1,
and named no test. `run-script-tests.sh` sets `set -e`, sixteen status tests invoked
`python3 gen_status.py` bare, and the first non-zero return killed the runner — **43 tests
abandoned, with an exit code that looked exactly like one honest failure.** This is the
failure `docs/conventions.md`'s harness contract names in its first row: *"an exit code cannot
show a suite that stopped running."*

`gen_or_fail` now turns a non-zero generator into one test's failure, at all sixteen sites.
Two details, both of which were wrong first:

- It is `|| return 0`, not `|| return`. Returning the helper's `1` made the test function
  return `1`, and `set -e` killed the runner at the top-level call — so the fix reported one
  failure and abandoned the rest, which is the same defect one step quieter.
- The helper captures the generator's output and prints it with the failure. A test that says
  only *"the generator exited non-zero"* sends the next reader back to reproduce it by hand.

**The suite has no floor.** `make checks` would still pass a run of zero tests. That is the
harness contract's second row and it is not this chore's to add.

`C37-M1` is the one worth keeping in view. It is not a hypothetical: it is the bug that shipped
in the first draft of this chore, and the check that catches it was written *after* the bug and
*because of* it. Had the diff been published as a paragraph rather than as a command, the
truncation would have merged.
