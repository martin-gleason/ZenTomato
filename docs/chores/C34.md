# C34 — the register's decisions, generated; and a validator for the file that is now canonical

**Kind:** chore. No user-visible change — no Swift source is touched.
**Owner:** agent.
**Opened:** 2026-09-23, implementing `D37` (ratified 2026-09-22), plus a validator owed by the
evidence of three consecutive units rather than by a delta.
**Branch:** `C34/generated-decisions-and-a-validator`

---

## The defect

### Half one — two documents each hold part of the answer to *how many decisions are there*

`docs/plans/00-deltas.md` defines **43** deltas. `docs/plans/00-register.md`'s `## Decisions (D)`
table contained exactly **one** row, `D30`. So `docs/plans/00-status.md` printed
`| Decisions (`D`) | 1 | 1 | 0 | 0 |`.

Neither source is wrong about itself and neither is complete. That is the second intake path
`docs/conventions.md` forbids — *"a second document is a second intake path"* — already producing a
wrong number on a page a CI check keeps current. `D37` ruled: the section is **generated** from
`00-deltas.md` by `scripts/gen_status.py`. Neither hand-maintained nor retired, because *"a register
that omits the largest register in the project is not a register."*

### Half two — a hand audit is a snapshot, not a gate

Three units in a row have now demonstrated the need for a row-shape check, each with a concrete
failure and none of them hypothetical:

| Unit | What got through |
|---|---|
| `C33` | Seven chore rows carried a stray 7th cell copied from another table's column. `gen_status.parse_tables` builds a row as `{header[i]: cells[i] for i in range(min(len(header), len(cells)))}`, so **a surplus cell is dropped with no warning**: `Why` parsed as the literal string `@chores`, the real reasoning landed in `TD`, and the Todoist id was discarded. `make check-status` stayed green throughout. |
| `C33` | Two rows carried an unescaped `\|` inside backticks, which ends the row early in strict renderers. |
| `C36` | `C33` repaired ten rows and left one behind — **and its own fix caused it.** Correcting `C15`'s status used `rstrip(' \|')`, which stripped the trailing pipe *and the empty `TD` cell with it*, leaving five fields against a six-column header. `C33`'s commit message says *"column-count audit: 0 malformed rows across all 7 sections"* and **that was true when it ran**: the `C15` edit came afterwards and nothing re-ran it. |

So each of the validator's rules exists because something specific got through. None is a matter of
taste.

## Three defects this chore found for itself

Both were found by running the shipped code against the shape it is about to be given, not by
reading it.

**1 · `gen_status.ROW_ID` silently drops `D6b` and `D21b`.** The bare form is
`[A-Z]{1,2}\d+`, which does not fullmatch a retrofit letter, and the second alternative requires
`-M`. So a generated table of 43 rows would have been counted as **41** on the page, in silence —
the identical failure mode the scoped-mutation widening was written for one character over, and the
identical failure mode `D38` opened the register to prevent. `docs/conventions.md` is explicit that
a retrofit letter is a legal identifier. Measured:

```
D6b          old=False    new=True
D21b         old=False    new=True
MUTATION-X   old=False    new=False
```

The bare alternative gains `[a-z]?`. It widens by a letter and not by a shape, so `MUTATION-X` is
still refused — `C33-M3` pins that half and stays green. **Verified to change nothing on today's
file:** every one of the seven sections matched the same rows before and after
(`O 31 · D 1 · C 29 · A 19 · M 103 · H 32 · RR 4`, `newly_matched=[]` in all seven).

**2 · `gen_status.sort_key` reports four correctly-ordered pairs as out of order.** It cannot parse
a scoped mutation id, so it degrades to `(unit_id, 0, "")` and compares lexically:

```
M   old: 4 out-of-order [('C32-M9', 'C32-M10'), ('F8-M9', 'F8-M10'), ('F8-M13', 'F10-M1'), ('F14-M9', 'F14-M10')]
M   new: 0 out-of-order []
```

All four are correctly ordered. Shipping `R6` as an error on that key would have failed a correct
file on its first run, and *"a validator that fails on something harmless gets disabled."* The key
is widened **in `gen_status.py`** to `(prefix, number, letter, scope-prefix, scope-number,
scope-letter)` and the validator **imports** it. One key, two consumers, so the page's row order and
the validator's rule cannot drift into disagreeing — which is `D37`'s *nothing is maintained twice*
applied to code.

---

**3 · `gen_status.parse_tables` and `check_register_rows.py` disagreed about where a cell ends, and
the disagreement made a closed row render as open.** This one was found by the unit's own gates,
after both halves were built, and it is the most instructive of the three because each file was
internally consistent and correct in isolation.

`gen_status.parse_tables` split a row with `line.strip().strip("|").split("|")`. The validator split
on `(?<!\\)\|`. So for any row carrying an escaped pipe inside a code span, the two read different
cells: the validator saw a well-formed row and passed it, while the generator ended the cell early
and shifted **every later field one column left**. The instance was `C34-M6`'s own register row,
whose `Status` cell reads `closed` in the file:

```
ODD ROW: {'id': 'C34-M6', 'title': 'Put a raw `\\', 'p': '` inside a backticked cell of the `H1` row',
          'status': '', 'run': 'closed', ...}
```

`Status` came back empty, `Run` came back holding the status, and the page printed
`| Mutations (M) | 118 | 42 | 1 | 75 |` — one row reported as `unknown` and one closed row not
counted closed. A confident wrong answer on a CI-enforced page, which is the class `D37` was opened
to fix, reached from **inside** the unit built to stop it.

Three things follow, and they are the reason this is recorded rather than quietly fixed:

- **The validator could not catch it, and still cannot.** By its own tokenizer the row is well
  formed. R1–R9 are rules about a file; this was a disagreement *between two readers* of that file,
  which no single-reader rule can see. Its evidence is therefore a generator test,
  `anEscapedPipeDoesNotShiftARow`, and mutation `C34-M16` — not a validator rule.
- **The fix is the same one ruling 4 already made for `sort_key`: one definition, two consumers.**
  `table_cells()` now lives in `gen_status.py` and the validator imports it. Restating a rule is how
  two readers of one file come to disagree about it. The validator still counts cells itself and
  compares the count to the header — that is R1, and it is a different job from tokenizing.
- **It made the validator's own advice false, which is a validate-every-artefact defect.** R2's message
  tells a human *"write it `\|`"*. Before this fix that advice did nothing: the generator ignored the
  escape. `C36`'s register row had already recorded *"escaping it as a backslash-pipe DID NOT WORK …
  a cell cannot contain a pipe at all, escaped or not"* and asked `C34` to document the limitation.
  `C34` removed the cause instead, and that row is marked superseded. An escaped pipe now
  round-trips: `C34-M16`'s row carries one and reads back `closed`.

The register row for `C34-M6` was itself rejected by the validator when first written, for a raw pipe
in `split("|")`. That is the check working on its own author in the same afternoon it was built.

## What was built

### 1 · `## Decisions (D)` is a generated region inside a hand-maintained file

One HTML-comment marker pair sits inside the section, below its hand-maintained preamble:

```
<!-- BEGIN GENERATED: decisions — … -->
| ID | Title | P | Status | TD |
…43 rows, sorted…
<!-- END GENERATED: decisions -->
```

`gen_status.py` splices `text[:end of BEGIN] + rendered + text[start of END:]` and touches no byte
outside that span, so the preamble above it and `## Chores (C)` below it stay hand-maintained prose.

- **The source is the definitions, not the index.** For each `## D<n> — <title>` heading, with
  fenced blocks blanked first exactly as `DeltaIntegrityTests.deltaFileLines` does (`D15` quotes
  `## Days` inside a fence). The index's own titles are **paraphrases** of the definition headings —
  index `D23` reads *"…; scope was never exceeded"*, the definition reads *"…. No spec text
  changes."* — and no test checks the index's `Status` column, while
  `everyDeltaCarriesAStatus` already enforces the window rule the generator uses.
- **Status** is the first match in the six lines from the heading, in this precedence:
  `REJECTED` → `rejected`, `RESOLVED` → `resolved`, `Ratified` → `ratified`, `Proposed 2` →
  `proposed`. **The precedence is load-bearing:** `D37`'s own window reads *"Proposed 2026-09-22.
  Ratified by the owner 2026-09-22."* and must come out `ratified`. A window matching none of the
  four exits 1 naming the id rather than emitting a blank — a blank would be `unknown` rendered as a
  confident answer.
- **All 43 rows**, and today's five columns unchanged — `| ID | Title | P | Status | TD |`, byte
  identical to the header that was there. Keeping the header identical is what keeps
  `parse_tables`'s header-keyed lookup (`p`, `status`, `title`) hitting.
- **Titles go through `one_line()`**, so pipes are escaped and the cell is length-capped. `D6` keeps
  its `~~strikethrough~~` and `D9` keeps `**RESOLVED by D18, 2026-08-23**`: `docs/conventions.md`
  says a rejected decision stays struck.

### 2 · The owner's two fields survive by merge, and the merge refuses to lose anything quietly

`D30` carries `P0` and `td:6hPjPm4FcP3gJ4Cj`; `00-deltas.md` has a column for neither, so
regeneration would have deleted a live Todoist link. A new hand-maintained section
`## Decisions — owner fields` sits immediately before `## Decisions (D)` and holds them.

The generator merges `P` and `TD` into the generated row for each ID named, writes `—` for an absent
`P` and an empty cell for an absent `TD` (41 existing register rows already carry an empty `TD`), and
**never writes the overlay**. An overlay row naming a `D<n>` that `00-deltas.md` does not define, or
a duplicate overlay ID, exits 1 naming the ID — a Todoist link keyed to a decision that does not
exist is `C33`'s dropped-`TD` cell one file over, and the whole point of this unit is that such a
loss is loud.

The heading deliberately **does not** end in `(D)`: `register_rows()` collects only sections matching
`\(([A-Z]{1,2})\)\s*$`, so the overlay is not counted as a second `D` register and `D30` is not
double-counted. Verified by reading the page, not by reading the regex.

**Three alternatives refused, named so they are not re-proposed:** dropping `P`/`TD` and *"recording
the loss"* (deletes a link the owner's own sync uses, and puts in prose what belongs in a field); a
generated table without those columns (moves the header, so the page's `p` lookup misses, and leaves
the Todoist id nowhere to live at all — deletion dressed as schema simplification); a separate
overlay file (a second document is a second intake path, and costs the register the one-read property
`conventions.md` values it for). Adding `P`/`TD` columns to `00-deltas.md` is refused hardest: that
file is the ratification surface and its rows are not edited.

### 3 · `--check` now judges two artefacts

The generator has two outputs and one of them is an input to the other. So, in one run: **splice the
region in memory → run `register_rows()` against that spliced text → build the page from it → write
both files.** Writing the region and then building the page from the on-disk pre-splice text makes
`make status` immediately followed by `make check-status` fail for a reason nobody caused; `C34-M14`
pins it, and `C28`'s existing `statusCheckPassesWhenGenerated` is what goes red.

`--check` recomputes both from the same in-memory pipeline and compares both against what is
committed, printing a unified diff for whichever differs and **naming the file** in the `FAIL` line —
today's message named no file, because there was only one. This is `docs/conventions.md`'s
validate-every-artefact rule: the generator's second output gets the judgement the first one
already had.

**A deleted marker fails loudly in both directions.** Exactly one `BEGIN`, exactly one `END`, `BEGIN`
first. Any other count exits 1 and writes nothing, **in write mode as well as under `--check`**. The
trap avoided is a generator that, finding no region, silently appends or silently writes nothing and
prints success — which is `O42`'s defect rebuilt one layer in.

### 4 · `scripts/check_register_rows.py` — nine rules and a floor

Python rather than bash: `check-open-register.sh`'s awk pipe-count cannot tell `\|` from `|`, and
this file uses escaped pipes legitimately; and the validator must **import** from `gen_status.py`
rather than restate it. It imports `SECTION_SYMBOL`, `ROW_ID` and `sort_key`, so a section cannot be
validated that the generator ignores, or ignored that the generator counts. It **counts cells from
the raw line itself**, splitting on `(?<!\\)\|`, and deliberately does not reuse `parse_tables`'s
dict comprehension — silently dropping the surplus cell is the exact defect `R1` exists to catch.

Every markdown table gets `R1`–`R3`. `R4`–`R8` apply to sections whose heading ends `(SYM)`.
**No warnings: every finding is an error.** A warning printed inside a green CI step is invisible,
which is the *"do not edit by hand"* header with nothing behind it — `C28`'s whole lesson.

| Rule | What it checks | The failure it exists to catch |
|---|---|---|
| `R1` | cell count equals the section header's | `C33`'s seven surplus-cell chore rows, dropped in silence; and `C36`'s `C15` row |
| `R2` | no cell holds an odd number of backticks | `C33`'s two rows with a raw `\|` inside a code span. Such a row usually trips `R1` too — but if a second defect restores the count, `R1` sees nothing, so this catches the mechanism rather than its arithmetic consequence |
| `R3` | no duplicate ID within a section | the `O23`/`O24`/`O25` collisions `## Defect — reused IDs` records and `C29` paid for. Zero duplicates today, so its evidence is `C34-M7` and not a passing run |
| `R4` | every row in a `(SYM)` section has a non-empty status | `conventions.md`'s own instance, *"a status page that reported `open` for rows nobody had given a status"*. **Fires on zero rows today** — its only evidence is `C34-M8` |
| `R5` | status is in a pinned vocabulary; `unknown` only for nine named legacy rows | `C33`'s finding that `gen_status.py` maps an absent status to the string `unknown` too, so the page cannot distinguish a row saying `unknown` from a row saying nothing. `C33`'s Chores preamble predicted that an empty-cell check would fire on **zero** of the nine rows it was written for; it was right, and this shipped as enum membership instead |
| `R6` | every `(SYM)` section is sorted by ID, on the scope-aware key | `conventions.md`: *"It was got wrong three times in one file that way"* |
| `R7` | every ID matches `gen_status.ROW_ID` | the bare-only filter that rejected all 81 scoped mutation ids **without a word**, and — found by this chore — `D6b` and `D21b` |
| `R8` | header's first column is `ID` and a `Status` column exists | `parse_tables` keys rows off the table's own headers, so a renamed column makes every lookup **miss** and the page renders `unknown` for the whole section under a confident label. `D38` proposed the column name `Mutation`, which would have rendered blank everywhere |
| `R9` | exactly one `BEGIN`/`END` marker, `BEGIN` first | **No past failure.** Defence in depth for the mechanism `C34` introduces, and labelled as such rather than given a borrowed justification. The generator refuses the same condition, so `make check-register-rows` alone names the cause instead of handing the reader a diff |
| floor | fewer than 7 `(SYM)` sections, or any with zero rows | the vacuous-read class `test_licence_check_refuses_an_empty_read` already exists for. **218+ rows is not pinned** — a number that churns on every row added is a number people edit to keep quiet |

The validator deliberately does **not** re-check the region's *contents*: equality is `--check`'s
job, well-formedness is the validator's, so the two cannot drift into disagreeing about one property.

## Rulings this chore takes

None needs a delta: `D37` ratified the mechanism, and the status vocabulary is the *implementation*
of `conventions.md` Axis 2 rather than a change to it. **The one place that judgement is exposed is
flagged for the owner at the bottom of this section.**

1. **`ratified` and `resolved` are closed; `held` is open and stays open.** `gen_status.CLOSED` did
   not contain `ratified`, so without this forty ratified deltas would have been counted **open** and
   printed in the owner-owned open table — a wrong number of exactly the class `D37` was opened to
   fix. `held` (`O37`, since `D39`) is **not** added: it is outstanding work parked on the owner, and
   the page's current behaviour — prints it verbatim, counts it open — is already right. Both halves
   are now things that can fail: `C34-M12` and `C34-M13`.
2. **The generated table carries all 43 deltas and keeps today's five columns.** `D37`'s own text
   refuses omission, and any subset rule is a second judgement nobody ratified. The index's main job
   is answering *"what is the next free number"*, which a filtered table cannot do. The cost is paid
   in `00-register.md`, where a reader is already inside a named section, and **not** on
   `00-status.md`: with ruling 1 only `D30` is open, so the open table does not gain a row.
3. **Owner fields survive by merge from a hand-maintained overlay inside the same file** — see
   *What was built · 2*, with the three refused alternatives.
4. **Unsorted is an error, on a scope-aware key shared with the generator** — see *Two defects this
   chore found for itself · 2*.
5. **`unknown` is outside the vocabulary, allowed only for nine named legacy chore rows** — `C9`,
   `C10`, `C12`, `C14`, `C15`, `C16`, `C18`, `C19`, `C20`. **A set of IDs, not a count:** a count of
   nine permits nine *different* rows to be swapped in. Each owner ruling deletes an ID, and the set
   can only shrink.

**FLAGGED FOR THE OWNER, not assumed.** `docs/conventions.md` Axis 2 pins
`proposed · ratified · rejected · superseded`. This project's vocabulary adds `resolved` (`D9`'s own
heading says `RESOLVED`; the generator reports the source's word rather than translating it to
`superseded`) and `held` (`O37`, since `D39`). If a pinned register vocabulary is **contract** rather
than implementation, then `resolved` and `held` owe a `D<n>` and this paragraph is where to say so.
It is one line of code either way. Recorded rather than decided silently.

**The two ids are redacted in that quotation, and the reason is the finding.** Pasting the failure
message verbatim into this file made this file cite them, and the next run failed again naming *this

particular failure reproduces it.** `D<a>` was the unused number the overlay mutation used; `D<b>` was

number used as a citation** — the register's own header already warns against exactly that, and the
fix is the by-name form, *"the validate-every-artefact rule"*. **The other is subtler and is a constraint
worth stating: a mutation whose whole point is naming a delta that does not exist cannot be
documented by spelling that number**, because the document then cites it and the walk refuses it,
correctly. The rows now describe the id instead of spelling it. Nothing was loosened to accommodate
this; the prose changed.

result being believed.** `C34-M4`'s first two attempts asserted `'## Decisions — owner fields' not in

`C34-M9` asserted a status cell's current value from the brief (`closed`) rather than from the file
(`open`). In each case the script raised and no result was recorded — which is the discipline
`statusCheckCatchesAHandEdit` was written for after it failed the first time it ran for exactly that
reason. **Assert your own mutation landed before asserting anything about the result.**

## One incident during the build, recorded because the file it damaged is this unit's subject

Partway through, roughly a hundred lines of **uncommitted** work in `docs/plans/00-register.md` — the
overlay section, the marker pair and the generated region, and this unit's mutation rows — were lost
and had to be rebuilt. The cause was a file-editing tool applied to a copy of the file that was
already stale, which wrote the whole file back and silently reverted every change made since. The
file had been *read* through shell commands rather than through the editing tool, so the guard that
normally refuses a blind overwrite had nothing recorded to compare against.

It is written down for three reasons, none of them incidental to `C34`:

- **`docs/conventions.md` already has this exact rule**, under *"Read the plan before you write it"*:
  the file-writing tool refuses to overwrite a file it has not read this session, **and shell
  redirection has no such guard.** That paragraph exists because `docs/plans/F7.md` lost 153 lines the
  same way. This is the second instance, one tool over: reading by shell and writing by tool defeats
  the guard just as thoroughly as writing by shell.
- **Nothing in the repository noticed.** Every gate passed on the reverted file, because a register
  with the C34 region absent is a perfectly well-formed register. The validator this unit ships cannot
  detect this and is not meant to; it is a shape check, not a content check. Recorded so the gap is
  not mistaken for coverage.
- **The rebuild is most of the argument for `D37`.** The generated region and the page were restored
  by running `python3 scripts/gen_status.py` — 43 rows, byte-identical, no judgement required, and
  `D30`'s `P0` and Todoist id came back out of the overlay. What had to be *reconstructed by hand* was
  only the part that is hand-maintained. A thing maintained once is a thing that can be regenerated
  after a mistake; a thing maintained twice has to be remembered.

Every mutation was re-run against the rebuilt file, and the results in the table above are from those
runs, not from before the loss.

## What this does not do

- **`docs/reviews/OPEN.md` is not generated here.** That is `C37`, already a row in the Chores table,
  and it must not happen before this validator exists and passes.
- **It does not validate row *content*, only row shape.** `C33`'s other failure — a cell asserting a
  provenance partition the file it cited contradicted, because a literal grep cannot see a range like
  `F8-M10–M13` — is untouched and uncatchable by this script.
- **It does not check prose against the tables.** The Chores preamble's stale *"eight of the 26
  rows"* is corrected by hand in this unit and no rule is added for it: one occurrence, and
  `DeltaIntegrityTests.theIndexStatesTheNumberOfDeltas` is the precedent for how such a rule is
  written when it earns one.
- **It does not gate `00-deltas.md` itself.** That file is checked only by `DeltaIntegrityTests`,
  which needs `xcodebuild`, so a machine with no Xcode has **no gate on the ratification surface**.
  A real hole, recorded, not filled here.
- **It does not resolve `OPEN.md`'s colliding ids** (two `O23`s, two `O24`s, two `O25`s). The
  validator does not read `OPEN.md` at all. This is a precondition `C37` must clear.
- **It does not change `check-open-register.sh`.** Its awk pipe-count keeps covering `OPEN.md`;
  subsuming it is `C37`'s business, because the two files have different headers per section and
  different owners.
- **It does not rule on the nine `unknown` chore statuses.** Establishing each means reading that
  chore's file and git history, which is research.
- **It does not touch the app.** No Swift source is edited; the only Swift that runs is the existing
  suite, as a gate.
- **One residual, stated rather than fixed:** a delta title longer than `CELL_LIMIT` is truncated by
  `one_line()`, and a cut that lands between two backticks would produce an odd backtick count. The
  longest title today is 87 characters against a limit of 100. If it ever happens, `R2` fails the
  build — which is a loud failure and not a silent one, and that is the property being relied on.
