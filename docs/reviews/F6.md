# F6 — adversarial review log

**Branch** `F6/stats-export` · **Reviewed** 2026-08-24 · **Reviewers** three, one per lens
(counting truth, scope and the gamification fence, readability) · **Verdict from all three:
DO_NOT_MERGE on first pass.**

The build itself was never verified by the workflow that wrote it: nine agents ran, and the five
after the two engineers — the build verifier, all three reviewers, and remediation — died on repeated
API 529s having executed zero tool calls. So F6 arrived as ~7,378 insertions of never-compiled
Swift. Everything below was established afterwards.

## Blocking findings, fixed

**The end-of-block prompt could be lost entirely.** `.sheet(isPresented: $showingHistory)` had no
`onDismiss`, and the only consumer of `pendingReflection` was an `onChange` on the offer's arrival.
A work block ending behind the history or settings sheet had its offer skipped — SwiftUI will not
present a second sheet from the same view — and nothing re-fired afterwards, so the next block's end
overwrote it. The taps survived; the sentences explaining them and that block's Todoist write did
not. F6 turned this from theoretical into likely by making the history button live mid-block.
Fixed in `f826157`.

**D21b under-cleared.** `SprintBoundaryObserver` clears on the *transition* into rest, so an id
recorded while the timer was already resting was swept by nothing until the end of the next sprint —
withholding that task for all of it, the exact failure D21b exists to prevent, inverted. The write
is now gated on the same predicate the observer uses. Fixed in `f826157`.

**D7 was widened without a delta.** D7 grants the raw-point-size exception on the stated condition
that "both are consumed at exactly one call site". The history screen became a second consumer of
`Typography.numeralBaseSize` and stated the deriving ratio inside the screen file, while
`Typography`'s own documentation still claimed a single call site — a file asserting a guarantee that
no longer held. `statNumeralBaseSize` is now a role in the token layer. Fixed in `5e5146f`.

**The build contract was untracked** while this branch committed an amendment to `F3-contract.md`
pointing at it, and several source files cite it as authority. Fixed in `def5777`.

**Three tests that could not fail.** Each was proved missing by mutation, and each new test was then
proved to catch that mutation:

- Changing `document` from `rangePeriod` to `todayPeriod` — turning the fortnight export into a
  one-day page — left all 407 tests green. `statsScreenMatchesExport` could not catch it because its
  seam, `StatsScreenModel(periods: { _ in period })`, ignores the range it is asked for, so screen
  and page were compared while both held the identical value.
- Deleting the picker's D21b filter left the suite green.
- Replacing D21b's `record` call with a discard left the suite green.

Fixed in `5ef14dc`. Both D21b sites are optional environment lookups that fail open silently, which
is why they are now pinned by a search of the source: they live inside SwiftUI views and are not
reachable without a live `@Query`.

## Open — the owner's to rule on

**1. The `## Projects` section is broken on real data, and the golden hides it.**
`SessionPlanStore.attachment(for:)` writes `projectTitle: nil` for every planned *task*, so on a real
export the section answering "where did the time go" collapses to one `**No project**` heading with
everything beneath it. The golden shows a healthy `**Thesis** — 7 pomodoros` only because
`StatsPeriodFixture` hand-sets the title. Two reviewers reached this independently, and
`StatsCountingTests.aTaskAttachedBlockAsTheAppActuallyWritesItToday` already asserts
`period.projects.map(\.title) == [nil])`, so the defect is recorded honestly in the suite.

This is an F3 defect that F6 exposes, and F6's done-when depends on it. `SPEC.md` F6 requires "counts
per task, project, day". Three ways out:

- **Spec delta on D17** — `SessionPlanItem` gains a fifth stored property so the plan snapshots the
  project name beside the task name. Honest and permanent, but reopens a ratified fence
  (`planItemHasFourStoredProperties`).
- **Resolve at attachment time from the local Todoist mirror** — no new stored field and no network,
  but `Item` does not carry `projectID` either, and it trades the snapshot principle for a lookup.
- **Open `F3b`, and make the fixture honest now** — change `StatsPeriodFixture` so the golden shows
  the shape real rows produce, ship F6 truthfully, fix the attachment in a scoped retrofit.

Recommended: the third. F6 counts and prints correctly; the bug is in what F3 records. A golden that
flatters the app is the worse outcome, because the golden is the artifact being signed off.

**2. `Thu 20 Aug, 00:05` is a date and time that never happened.** The tap was at 00:05 on Friday 21,
inside a block that started 23:50 on Thursday. The day comes from the block and the clock time from
the tap, printed as one pair with no marker, and the decoding key — the day-attribution rule — is
nowhere on the page. Suggested: render `Thu 20 Aug, 00:05 (after midnight)`, carrying a
`crossedMidnight` flag set in `StatsQuery` where `StatsDay.containing(tap) != block.day`. Left
unfixed deliberately: it changes the format of the artifact the owner signs off, and D15's own rule
forbids regenerating a golden to make a test pass.

**3. Taps inside a stopped block still count.** In the golden, Tue 18 Aug shows 0 pomodoros and 1
external distraction. D15's heading says "abandoned blocks are excluded from *every count*" while its
body argues only about the pomodoro figure, and `F6.md` separately says a distraction belongs to the
work block it was tapped in. The two rules collide and the code picked one. Internally consistent —
every total reconciles — but a reader computing distractions-per-pomodoro has a numerator including a
block absent from the denominator. Needs ratification, not a comment in a test.

**4. The H1 is the only ISO date** in a document where every other date reads `Sat 8 Aug`. Argued in
the contract (a page in a notebook must state its year) but never named in a PR as the exception it
is. `# ZenTomato — Sat 8 Aug to Fri 21 Aug 2026` keeps both properties.

**5. `## Repeating` discards the counts it exists to report.** `Pick 1–3 MITs — Mon, Wed, Thu, Sat`
comes from a fixture holding five completions across four days, including two on Monday 10. A habit
kept ten times and one kept four render identically. Suggested: `kept 5 times on 4 days (Mon, Wed,
Thu, Sat)` — both figures are already on the group.

## Non-blocking, not fixed

- `try?` on the three `StatsQuery` fetches turns a refused read into a confident "you did nothing",
  on the one screen whose premise is being trusted, and into `No pomodoros in this range.` in a
  document filed as truth. The app already has the right pattern for this: `exportUnavailable = "The
  export couldn't be prepared. Your history is fine."`
- `noIdentifiersInOutput` is largely tautological — the fixture contains no identifiers, so four of
  its five string assertions cannot fail. The *structural* guarantee is real: no value type feeding
  the document can hold an identifier. Build the document through `StatsQuery` from
  `StatsStoreFixture`, whose rows carry ids like `td-task-habit-0001`.
- Main-thread disk I/O: `refreshExport()` renders the whole document and sweeps the temp directory
  synchronously on the MainActor, eagerly on every range change, whether or not anyone taps Export.
- The temp sweep deletes every `ZenTomato-*.md`, including one an open share extension may still be
  reading.
- Dead app code with load-bearing documentation: `StatsRange.everything(endingOn:in:)` and
  `StatsPeriod.recordedSpan` have no caller outside tests, and describe an all-time export the range
  control does not offer.
- `StatsRange.swift:35` states the opposite of the shipped UI — "no free-form date pickers" against a
  control whose own header says "Two pickers and a reset. No presets."
- Markdown metacharacters in Todoist titles are not escaped: a task named `**Thesis**` renders as
  markup.
- A device changing time zone re-attributes historical days, so two exports of the same fortnight can
  disagree. Correct across DST — every boundary goes through `Calendar`, never 86,400-second
  arithmetic — but the time-zone case is unspecified and untested.
- The performance test asserts `< .seconds(1)` against a 16 ms budget, so a 60× regression passes.
- The palette lint rule's `included` regex does not cover `Stats/`, `Export/` or `Sprint/`. Nothing
  violates it today — zero `Palette.`, zero colour literals, zero raw fonts — but the guard has a
  hole.
- The no-writes fence test forbids `create`, `move`, `reopen`, `POST /tasks` but not `update` or
  `comment`, two of the four words CLAUDE.md's hook names. The real gate
  (`todoist-allowed-endpoints.txt`) is untouched, so the test's comment overstates it.

## Cleared on the merits

- **The counting rules.** Read line by line. `CountedBlock.init?` is the whole rule, `fileprivate`,
  with no second copy. No total is stored anywhere — every figure is reduced over rows — so a heading
  cannot disagree with its own sub-rows. Correct across DST.
- **One counting path.** Traced both call paths: `load()` makes exactly two `periods(_:)` calls, the
  three lists and the export all read the same stored value. No view performs arithmetic;
  `StatsQuery.swift` is the only Stats-side file touching `FetchDescriptor`/`#Predicate`.
- **D21 recurrence cannot be silently always-false.** `is_recurring` is read from inside `due`, where
  Todoist actually puts it — confirmed against Doist's own API v1 client, not the docs SPA. `due` is
  optional and `Due.init(from:)` uses `decodeIfPresent ?? false`, so a real account cannot fail to
  decode. `recordLocally` reads the mirrored row *before* the delete three lines down, and
  `CompletedTaskRecord.init` has no default for `wasRecurring`, forcing the call site to state it.
- **Todoist writes.** `TodoistAPI.swift` and the allowlist are byte-untouched: four endpoints, one
  `POST`, the close command.
- **Scope and the gamification fence.** No chart, ring, streak, badge, best-day, trend, theme,
  widget, Watch, Mac or CloudKit implementation; the only grep hits are doc comments forbidding them.
  No capture surface. `.swiftlint.yml`, `Makefile`, `scripts/`, `.github/`, `Config/`, `project.yml`
  and `docs/specs/` are byte-identical to `main`: no limit raised, no rule disabled, no new
  `swiftlint:disable`.
- **D16, designed-not-prepared.** No sync scaffolding, no dirty/pending flag, no queue, no conflict
  resolution, no local task model. D21b's set is an in-memory `Set<String>`, never persisted.
- **The entry point.** The finding this repo has most reason to fear, after F3 lost an entire feature
  to a suppressed affordance. Present and enabled in every state including no-data, zero layout
  points, no `.disabled(`, 44-point hit area, labelled for VoiceOver, no badge — and
  `StatsFenceTests.theWayIntoTheHistoryIsAlwaysThere` asserts both the overlay line and the absence
  of `.disabled(`. D19 satisfied.
- **Accessibility.** There is no table on the screen, so nothing to clip: rows switch `HStack` to
  `VStack` at `.accessibility1`, every row carries a label and value, and the I/E figures are spoken
  as words through `DistractionTally`. AX5 previews exist for every state including the empty ones.
- **Empty states.** State facts, name where a stopped block went, never scold.
- **Untouched by this feature**, verified byte-identical to `main`: `AppSettings.swift`,
  `DistractionTally.swift` (hand-written by the owner), `TimerEngine.swift`, `TimerCycle.swift`,
  `PomodoroSession.swift`, `Distraction.swift`, `SessionPlanItem.swift`, `TodoistAPI.swift`.
