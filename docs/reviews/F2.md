## Blocking findings, and what closed them

1. **The boundary task cancelled itself, then scheduled the next block's alarm.**
   `TimerEngine.armBoundary()` begins by cancelling whatever `boundaryTask` points at. On the
   auto-start path it is reached *from inside that very task* — boundary task → `boundaryReached()`
   → `end()` → `begin()` → `armBoundary()` — so the task cancelled itself and then ran
   `await scheduleAlarm(for:)` with `Task.isCancelled == true`. `AlarmManager.shared.schedule` is a
   cancellation-aware system call, so every block after the first in an auto-started chain would
   have been scheduled from a dead task and ended in silence. That is the single failure this
   feature exists to prevent, on the path a person meets most often.

   Closed by having the woken task let go of the handle before it does any work, guarded by a
   generation counter so a *superseded* task cannot clear a newer one's handle. Regression test:
   `TimerBoundaryTests.chainedAlarmsAreScheduledFromALiveTask`, which uses the test clock's new
   waking mode so the task body genuinely runs, and a spy that records `Task.isCancelled` at each
   schedule. **Verified to fail without the fix** (`cancelledAtSchedule` came back
   `[false, true, true, true]`).

2. **An overdue boundary auto-started the next block.** A sleeping task does not fire while iOS has
   the app suspended — it fires the instant the app resumes. `boundaryReached()` passed
   `mayAutoStart: true` with no check on how late it was, so a phone picked up in the morning
   auto-started a break, contradicting ratified decision D-d. The outcome was also nondeterministic:
   on resume the overdue continuation and the app's own foreground reconciliation both queue on the
   main actor, and whichever ran first decided what the user saw.

   Closed with a lateness guard: more than `clockSkewTolerance` late and the boundary is handed to
   `synchronize()`, which records one block and goes idle whatever auto-start says. Regression tests:
   `overdueBoundaryDoesNotAutoStart` and, so the guard cannot become a switch that disables
   auto-start, `onTimeBoundaryStillAutoStarts`. **Verified to fail without the fix.**

3. **The sprint rule conveyed nothing at the default text size.** Filled and empty segments were
   `action` and `borderStrong` — 1.37:1 in light and 1.39:1 in dark measured against *each other*.
   WCAG 1.4.11 asks for 3:1 between things you must tell apart and 1.4.1 forbids carrying
   information by colour alone; a two-point rule in two colours of the same lightness failed both,
   and the team's own screenshot of a half-finished sprint was indistinguishable from a finished one.

   Closed by carrying the distinction in shape as well as colour: a finished segment is drawn at
   `Spacing.xxs` and an unfinished one at `Spacing.xxxs`, bottom-aligned, so the rule has a visible
   step. No new colour role, no new spacing step, no repainting. New test suite
   `SprintProgressTests` asserts the low colour contrast *as a recorded fact* and asserts the height
   ratio, so removing the step fails the build. Visible in the simulator capture
   `build/f2-evidence/r2-05-work-running-1-of-2.png`.

4. **No device evidence, and no review log.** `docs/reviews/F2.md` did not exist; nothing in the
   feature had been driven by a human finger. **This one is not closed** — see *Still open* below.

## Non-blocking findings acted on

- **A chained block inherited the previous block's failure message.** `lastFailure` was cleared by
  `start()`, `skip()`, `stop()` and `handleDismiss()` but not on the auto-start path, so an amber
  "this block won't sound an alarm" line stayed up over blocks whose alarms were fine. Cleared at the
  top of `boundaryReached()`; test `chainedBlockClearsThePreviousBlocksFailure`.
- **The test clock could not run the boundary task's body at all.** `sleep(until:)` always threw, so
  `armBoundary()` had zero behavioural coverage and `sleepDeadlines` was written and never read.
  Added a bounded waking mode and `restoredBlockArmsOneBoundaryAtItsEnd`, which asserts a relaunched
  engine arms exactly one wake-up at the stored end of the block.
- **Four settings rows were `Stepper`s.** See *Decisions taken for the owner* below.
- **VoiceOver read every settings value twice.** A consequence of the Steppers; gone with the
  Pickers, which carry their own label and value.
- **The running countdown's spoken value changed once a second.** The design spec forbids attaching
  a live-updating `.accessibilityValue`; whether iOS re-announces it is a runtime behaviour no
  comment can settle. Coarsened to whole minutes while a block runs (about 26 changes in a 25-minute
  block instead of 1,500), and the comment now says what is and is not known.
- **The alarm-failure row was silent to VoiceOver.** Announced on the transition from no failure to
  a failure, once, from `TimerScreen`.
- **`AlarmPermissionView`'s instructions named a step that does not exist.** The only button lands on
  ZenTomato's own page in Settings, where there is no "ZenTomato" row to tap. Copy rewritten to the
  route the button actually takes.
- **The Lock Screen card's documented truncation order was not implemented.** `.layoutPriority` sat
  on views inside VStacks while the HStack allocating the width saw neither. Moved onto the
  countdown's column; `SprintCount` now shrinks rather than clipping.
- **The Lock Screen's sprint count and kicker had no accessibility labels.** VoiceOver read "2 of 4"
  with no subject and spelled the uppercased kicker. Both now carry the same wording the app's own
  screen uses.
- **Three comments claimed guarantees the code did not provide**, which this project's own lint
  configuration calls out as worse than claiming none:
  - `AlarmKitScheduler`'s "the only file that mentions AlarmKit" — it is three files. Reworded to the
    true containment: the engine, the screens and every test name no AlarmKit type.
  - `FocusAlarmMetadata`'s claim that `AlarmMetadataTests` catches an un-shared copy — it could not,
    since the test target links only the app. Given teeth instead: `sharedSourcesAreCompiledIntoTheWidget`
    reads `project.yml` and fails if the shared directories leave the widget target.
  - `TimerEngineHolder`'s claim that reconciliation accounts for an unserviced Lock Screen dismiss —
    it does, but as a **completed** block. Now stated plainly. See *Still open*.
- **A sprint of one does not forbid short breaks.** Two doc comments and a footer said it did; a
  *skipped* focus block earns nothing and takes a short break there as anywhere. Behaviour kept,
  three comments corrected, and `skippedWorkInASprintOfOneStillTakesAShortBreak` added so the prose
  and the code cannot drift again.
- **Two comments pointed at later features by name.** Trimmed so they explain the omission without
  promising the work.

## Findings rejected, or whose proposed fix was rejected

- **"Add `action` on `borderStrong` to `borderPairings` at 3:1."** Rejected as written: that pairing
  cannot pass with the shipped roles, so following the instruction would have added a permanently
  failing test. The defect is real and was fixed by shape; the measurement is recorded in a test that
  asserts it *is* below the threshold, which is the honest form.
- **"Clear `lastFailure` at the top of `begin()`."** Rejected in favour of clearing it at the top of
  `boundaryReached()`. Clearing in `begin()` would wipe an `.alarmCancellationFailed` recorded
  moments earlier by `skip()` — a warning about a stale alarm that may still fire during the block
  about to start, which is exactly when it matters. `boundaryReached()` is the only path into
  `begin()` that did not already clear, so the narrower change is also the complete one.
- **"Change the cycle so a skipped block in a sprint of one earns the long break."** Rejected. The
  invariant that matters is that the long break is *earned* by finished pomodoros; the documentation
  was wrong, not the code. Comments corrected and a test added instead.
- **"Update the C4 row in `docs/plans/00-deltas.md` and the device-check heading in
  `docs/plans/F2.md`."** The finding is correct — both are stale now that C4 is closed — but the F2
  build contract explicitly fences those two files, and a remediation pass quietly editing the plan
  it is held to is the wrong shape. Recorded here for the owner to make in one edit:
  **C4 is closed (2026-08-22) and no longer gates the device checks in F2, F3, F4 or F7.**
- **"Signal that a short break longer than the long break is odd."** No code change. The six fields
  are independent by contract and adding a relationship between them is a seventh rule the spec does
  not authorise. Recorded as an accepted state.

## Decisions taken for the owner, and reversible in one instruction

**The four numeric settings rows are now `.pickerStyle(.navigationLink)` Pickers, not `Stepper`s.**
Two ratified documents disagreed: the F2 build contract's D-k said Steppers, the ratified settings
design spec §3.1 chose Pickers and rejected Steppers by name. Both reviewers who raised it said the
owner decides. The remediation took the design spec, because D-k's stated *reason* is the
no-capture-surface rule and a Picker satisfies it completely — there is still no text field, no
keypad, and the bounds are still the control rather than a validation step — while the cost of
Steppers is real and one-sided: moving the focus length from 25 to 120, or down to the 1 that makes
the eight-minute hand test possible, is 95 taps, and for a VoiceOver reader 95 swipes with no
long-press acceleration, on the app's only writable screen. The change is contained to
`SettingsView.swift` and the ranges still come from `SettingsBounds`. **Say the word and it goes back.**

## Still open

**The device check named in `docs/plans/F2.md` has not been performed, and this branch should not
merge until it has.** The remediation engineer cannot answer a permission prompt or photograph a
Lock Screen. Everything below is unverified by anybody:

- an alarm firing on time with the app backgrounded, the phone locked and a Focus turned on; and
  again with the app force-quit;
- `Silence.caf` actually silencing the alert when Sound is off — there is no silent case in
  `AlertConfiguration.AlertSound`, so this bundled file is the entire implementation of one of the
  six locked settings;
- the Live Activity appearing on the Lock Screen at all;
- the Dynamic Island in compact, minimal and expanded, including the 120-minute `1:59:58` case in
  the 56pt compact-trailing frame;
- whether `.islandInk()`'s `environment(\.colorScheme, .dark)` reaches the widget process — if it
  does not, the countdown is near-black ink on a permanently black capsule;
- whether `NSAlarmKitUsageDescription` is the right Info.plist key;
- what iOS actually calls the switch at Settings → ZenTomato, which `AlarmPermissionView` names as
  "Alarms" in its copy;
- whether VoiceOver re-announces the countdown's value when it changes, at the new one-minute
  cadence.

Two smaller things also remain open:

- **A Lock Screen dismiss that the app is not resident to service is recorded as a completed block.**
  `synchronize()` hard-codes `completed: true`, and the widget has no store, no shared file and no
  way to leave a note. The comment now says so plainly rather than implying a guarantee. Fixing it
  needs a field on `TimerState` and a cross-process channel, which is a decision, not a patch.
- **`docs/plans/F2-contract.md` is still untracked.** It is referenced by this log and by the PR and
  should be committed with the feature.

  was chosen, and it has not been tested with a Focus turned on. Everything else about the alarm works.
