## Blocking findings, and what closed them

1. **The no-writes hook scanned `.xcconfig` files**, which meant the credentials file
   `Support/Secrets.xcconfig` was inside the search path of a script that prints matching lines on
   failure — a route by which a client secret could reach a public CI log. Closed by dropping
   `.xcconfig` from the scan entirely: a Todoist call site cannot exist in a build-settings file, so
   nothing is lost.

2. **The URL-builder path failed open.** The hook matched literal Todoist URLs, so a URL assembled
   from a base plus a path fragment slipped past it. Closed, with a regression test
   (`noWritesHookCatchesBuilderPath`) that fails if it regresses.

3. **`gen-secrets.sh` required keys nothing yet reads**, so `make ci` could not go green on a
   repository whose `.env` predates this contract — which would have made F1's own done-when
   unreachable. Closed by making the required list empty at F1 while keeping the failure mechanism
   intact and tested via `--require`. Promoting the three Todoist keys is now a written precondition
   on F3.

4. **Build-log secret exposure.** Xcode exports every build setting into a script phase's
   environment, so `showEnvVars` or a stray `set -x` would print the client secret into the Actions
   log of a public repository — a leak gitleaks cannot catch, because it lives in logs rather than in
   the tree. Closed by setting `showEnvVars: false` explicitly and treating it as a security control.

## Findings rejected, with reasons

The remediation engineer declined three findings rather than appeasing them. Recorded because a
rejected finding is a decision, and decisions belong in the log:

- **Cap Dynamic Type on the kicker to restore the size ratio at AX5.** Rejected as treating a
  symptom: the ratio collapses only because the numeral was built from `.largeTitle` rather than the
  designer's `@ScaledMetric`, and the ratified spec bans Dynamic Type caps on this screen outright.
  Adding a cap would have quietly hardened a deviation instead of surfacing it. Escalated to the
  owner — see *Open decisions* below.
- **Bind method to path in the Todoist checker now.** Rejected for F1: implementing it means guessing
  the HTTP shape F3 has not chosen, and a checker built against a guessed shape is a second fail-open
  wearing a confident comment. Recorded as an F3 precondition instead.
- **Add a UI test asserting the rendered numeral string.** Rejected because reading text out of a
  SwiftUI view needs a UI-test target the scope fence forbids. The same finding's alternative — make
  the missing-row state visibly distinct — was taken instead, which removes the actual defect.
