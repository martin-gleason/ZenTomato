## Blocking findings, and what closed them

1. **The no-writes hook scanned `.xcconfig` files**, which meant the credentials file
   `Support/Secrets.xcconfig` was inside the search path of a script that prints matching lines on
   failure — a route by which a client secret could reach a public CI log. Closed by dropping
   `.xcconfig` from the scan entirely: a Todoist call site cannot exist in a build-settings file, so
   nothing is lost.

2. **The URL-builder path failed open.** The hook matched literal Todoist URLs, so a URL assembled
   from a base plus a path fragment slipped past it. Closed, with a regression test
   (`noWritesHookCatchesBuilderPath`) that fails if it regresses.

3. **`gen-secrets.sh` required keys nothing yet reads**, so `make ci` could not go green on a
   repository whose `.env` predates this contract — which would have made F1's own done-when
   unreachable. Closed by making the required list empty at F1 while keeping the failure mechanism
   intact and tested via `--require`. Promoting the three Todoist keys is now a written precondition
   on F3.

4. **Build-log secret exposure.** Xcode exports every build setting into a script phase's
   environment, so `showEnvVars` or a stray `set -x` would print the client secret into the Actions
   log of a public repository — a leak gitleaks cannot catch, because it lives in logs rather than in
   the tree. Closed by setting `showEnvVars: false` explicitly and treating it as a security control.

## Findings rejected, with reasons

The remediation engineer declined three findings rather than appeasing them. Recorded because a
rejected finding is a decision, and decisions belong in the log:

- **Cap Dynamic Type on the kicker to restore the size ratio at AX5.** Rejected as treating a
  symptom: the ratio collapses only because the numeral was built from `.largeTitle` rather than the
  designer's `@ScaledMetric`, and the ratified spec bans Dynamic Type caps on this screen outright.
  Adding a cap would have quietly hardened a deviation instead of surfacing it. Escalated to the
  owner — see *Open decisions* below.
- **Bind method to path in the Todoist checker now.** Rejected for F1: implementing it means guessing
  the HTTP shape F3 has not chosen, and a checker built against a guessed shape is a second fail-open
  wearing a confident comment. Recorded as an F3 precondition instead.
- **Add a UI test asserting the rendered numeral string.** Rejected because reading text out of a
  SwiftUI view needs a UI-test target the scope fence forbids. The same finding's alternative — make
  the missing-row state visibly distinct — was taken instead, which removes the actual defect.

# F1b — Secrets migration (retrofit)

**Reviewed:** 2026-08-22 · **Change:** `.env` pipeline replaced with Xcode-native `.xcconfig` (D6b),
plus `make device` for chore C4.

## Verdict: DO NOT MERGE (first pass) — 6 blocking, 12 non-blocking

### The finding that mattered

> *"The migration deleted the `.env` pipeline but left the `.env` credentials."*

After a change whose entire justification was secret hygiene, the only place a live Todoist client
secret and a live user access token existed was a file nothing reads, no document mentioned deleting,
and the owner would never think about again. Worse, the new guards *institutionalised* it: they
asserted only that `.env` stay git-ignored, with a message reading "a stray one must never be
committed" — blessing a live-credential file as a permanent resident of the working tree.

The right posture after D6b is not "keep it ignored". It is "this file is finished; delete it."

**Fixed.** The two build-time credentials were migrated into `Config/Secrets.xcconfig` by a script
that reports only value *lengths*, never values. `ACCESS_TOKEN` was deliberately not carried across —
`CLAUDE.md` says the user token lives in Keychain, and F3's OAuth flow obtains it — and
`VERIFICATION_TOKEN` is a webhook credential with no place in v0.1. `check-secrets.sh` now warns on
every run that a leftover `.env` is dead weight ageing unwatched, and says how to remove it. The
ignore check stays as a second line of defence for as long as one exists.

### Other blocking findings

2. **`docs/plans/F3.md` asserted a state that did not exist** — "credentials live in
   `Config/Secrets.xcconfig`" while both keys were empty. A gate precondition claiming something
   false is worse than one claiming nothing. Fixed, and the chore line pointing at rejected D6 with it.
3. **`check-secrets.sh` told the owner to put a found credential "in `.env`"** — the single most
   consequential message in the secrets system, pointing at the mechanism this change deleted. Fixed.
4. **`check-todoist-writes.sh` carried a security rationale built on deleted machinery** — it
   justified excluding `.xcconfig` files by describing a generator script and a file path that no
   longer exist. At this project's stated learning level the owner reads comments as documentation of
   a control, so a comment describing a control that is not what it says is a real defect. Rewritten.
5. **`run-script-tests.sh` kept a path to the deleted generator**, plus a stale banner, a stale count,
   and a stale claim about which files it touches. Fixed.
6. **`.gitignore` referenced `make secrets`**, a target deleted in the same change. Fixed.

### Non-blocking findings acted on

- `Config/App.xcconfig` declared `TODOIST_CLIENT_ID`, `TODOIST_CLIENT_SECRET` and a *concrete value*
  for `TODOIST_OAUTH_CALLBACK_SCHEME` — keys for a feature that does not exist, in a committed file.
  The reviewer called the callback scheme "the closest thing in the diff to preparing for F3". All
  three are gone; the file now declares only what today's build needs, and the template documents the
  rest. This is the scope rule working as intended.
- **A new committed file was an uncovered surface.** `App.xcconfig` sits beside the real secrets file
  with keys of the same shape, and a client ID pasted one line too high would have passed every
  check — the existing pattern looks for `secret`/`token`/`password`/`api_key`, and `CLIENT_ID`
  matches none. Added check 1c, which rejects any long opaque value in that file. Verified to exit 1
  on a pasted credential and 0 when clean.
- `install-device.sh` could exit **with no message at all** if `python3` were missing, because `read`
  returns non-zero at EOF and `set -e` takes over — precisely the bare `Error 1` the script exists to
  prevent. Status is now captured and checked. Verified by shadowing `python3` with a stub that exits
  127: the script now names the problem and the fix.
- The script printed the Team ID in a failure message — not a credential, but the only place a value
  from the private xcconfig was echoed. Removed.
- `App.xcconfig`'s diagram described Info.plist wiring that does not exist yet, presenting intent as
  implementation. Rewritten to say so.
- The non-breaking-space trick that keeps a device named "Marty's iPhone" in one field was invisible
  and uncommented. Now explained where it happens.
- A half-deleted `project.yml` comment left a headless fragment. Repaired.

### Findings not acted on

- **`ci.yml` can silently corrupt a secret containing `//` or `$(`** — xcconfig treats those as a
  comment and a substitution. Real, and left open deliberately: no Todoist key is written by CI any
  more, and the right place to handle it is the feature that first depends on a working value.
  Recorded on F3.
- **`docs/Pr-Review-log.md`** — an untracked file, off-convention, not created by this work. Left for
  the owner rather than moved or deleted.

### Deletion damage, assessed

Of four deleted script tests, three covered machinery that no longer exists. The fourth,
`genSecretsFailsLoudly`, covered a guarantee that still matters — nothing now fails when a required
credential is blank — and that debt is explicitly assigned to F3, which is the feature that first
reads one. `ENABLE_USER_SCRIPT_SANDBOXING: "NO"` was removed and the build verified clean without it;
it existed only so the deleted generator could write into the source tree, so the sandbox is back on.

### On D9

The reviewer independently confirmed the D9 analysis is accurate and not overstated: Todoist's OAuth
has no PKCE, the code-for-token exchange genuinely requires the client secret, and a token-exchange
service genuinely contradicts the *Local only* rule. One correction adopted: "a build setting becomes
an `Info.plist` entry" describes the wiring F3 will add, not the current build — nothing is plumbed
into `Info.plist` today.

### One more, found while staging the fix

Not from the reviewer — caught by inspecting what `git add -A` had actually staged.

Removing the `.env` pipeline included deleting `Support/Secrets.xcconfig` from `.gitignore`, because
nothing generates that path any more. But **the file itself was still sitting on disk** from the
previous design, so deleting its ignore rule made a secrets-shaped file stageable, and it duly
appeared as `A  Support/Secrets.xcconfig`.

It happened to be empty and was never committed, so nothing leaked. The mechanism failure is the
finding: a path-specific ignore rule protects only the path it names, and this change moved the path.

Fixed two ways. The orphaned file is deleted, and the ignore rule is now the bare `Secrets.xcconfig`,
which matches at **any** depth — verified against `Config/`, `Support/` and a nested path, with
`Secrets.example.xcconfig` still tracked. The `check-secrets.sh` basename guard was independently
confirmed to exit 1 on a force-staged `Secrets.xcconfig` holding a credential-shaped value, so the
pre-commit hook would have stopped this even had the ignore rule stayed wrong.

### Two misdiagnoses the script made, both fixed

Neither was a build defect. Both were the script confidently blaming the wrong thing, which is exactly
what it exists not to do — so both were fixed rather than worked around.

1. **"Developer Mode is off" — it was not.** The phone reported `developerModeStatus: enabled` and
   `tunnelState: disconnected`. A phone on Wi-Fi rather than a cable lets its tunnel go idle, and an
   idle tunnel produces the identical build error to Developer Mode being off, with the opposite fix.
   The script now wakes the tunnel before building, and when the error does appear it *asks the device*
   which cause applies instead of guessing.

2. **The wrong Team ID, and the documentation caused it.** `Config/Secrets.example.xcconfig` said to
   find the team with `security find-identity`. The bracketed code there — `S6F69FMX3V` — is a
   **personal** identifier. The Team ID is the certificate's **OU**, `KH6NBQRZBY`. They are visually
   identical and the wrong one fails as *"No profiles for com.martingleason.ZenTomato were found"*,
   which sends you to inspect the bundle identifier rather than the team. The guidance now gives the
   `openssl x509 … grep OU=` incantation and says explicitly which value is not the team.

   Worth noting the failure was silent in the useful direction: a wildcard profile `KH6NBQRZBY.*`
   already existed with this iPhone registered in it, so once the team was right, signing needed no
   Apple ID in Xcode at all.
