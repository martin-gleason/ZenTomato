The test fails if the real number EXCEEDS this one. At zero that means any delta ratified from now on
must reach SPEC.md in the same change, or the build goes red immediately. That is the behaviour the
ratchet existed to reach: for two months, twenty-two deltas were ratified and none was applied, and
nothing noticed.

HOW THE COUNT WORKS, AND WHY IT NEEDS NO MAINTENANCE
A delta owes an amendment when the text it says the spec CURRENTLY says is still present in SPEC.md.
Apply the amendment and that text is gone, so the delta stops being counted on the next run. There is
no list to keep in step. D2 was the first confirmation: applying it dropped the count from six to five
with nothing edited but the spec itself.

ONE THING THE DETECTOR CANNOT SEE, kept here as a warning rather than a live item:
  D18 quoted the spec as "OAuth sign-in." while SPEC.md read "OAuth sign-in;" — a full stop against a
  semicolon. Matching is verbatim on purpose, because fuzzy comparison buys one true positive at the
  cost of false ones, and a check that cries wolf stops being read. D18 has been applied, but it was
  never counted, so nothing about the number above moved when it was. A future delta that paraphrases
  the spec rather than quoting it will be invisible the same way. Quote exactly.

Never raise this number. Raising it is the act this file exists to make visible.
