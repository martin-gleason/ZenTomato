## Paraphrasing it back

ZenPom owes two credits and has nowhere to put them.

The first is a **licence obligation**. GPL §4 says a conveyed copy of the program owes its recipient
the text of the licence. A copy of the app is a conveyance, and `LICENSE` in the repository satisfies
the repository, not the app. `ZenTomato/App/AppLicence.swift` already discharges the storage half of
that — the notice, the App Store pledge and the source URL are compile-time constants, so a missing
notice fails to compile rather than surprising somebody at runtime — but a constant nobody can read is
not a notice given to anybody. **F11 is the half that puts it in front of a person.**

The second is the **sound attribution**, and it is stricter than any licence involved. Both bundled
bells are CC0, which demands nothing at all. The owner ruled that every sound is credited with a
link regardless. `docs/sounds/candidates.md` records the ruling in the same words: *"stricter than CC0
requires and applies regardless of licence."* That makes it an obligation the project gave itself,
which is the only kind that has to be enforced by something other than fear of a lawyer.

So: **one screen, reached from Settings, carrying the licence notice, the pledge, the source link,
the version, and every borrowed sound with its author, its licence and a link that can be followed.**
That is the whole feature. It is item 5 on cost, not on importance.

## What is already true, checked in the tree rather than assumed

**The gate brief for this feature said the sound attribution "does not exist yet". It does, and it is
better built than the brief expected.** Recording the correction here rather than discovering it in the
first commit, because a plan written against a stale premise decomposes into the wrong tasks.

| Thing | Where it is | State |
|---|---|---|
| GPL notice, App Store pledge, source URL | `ZenTomato/App/AppLicence.swift` | shipped, constants |
| Those words asserted present | `ZenTomatoTests/LicenceFenceTests.swift`, `theGplNoticeShipsInsideTheApp` | shipped |
| Per-sound author / licence / source | `AlertSound.attribution` in `ZenTomato/Alarm/AlertSound.swift` | shipped |
| The rendered credits paragraph | `AlertSound.credits`, a `static let` | shipped |
| The credits on a reachable surface | `SettingsView.swift:446` — the About section's footer | shipped |
| Every bundled file is credited, both directions | `AlertSoundTests.everyShippedSoundFileIsAccountedForAndEveryCreditIsReal` | shipped |
| The credits actually reach a screen | `AlertSoundTests.theCreditsOnScreenMatchTheSoundsThatShip` | shipped |

**The brief asked two questions. The tree already answers both, and the answers matter more than the
questions did.**

*Is every bundled sound actually attributed?* Yes, and by a fence that reads the directory rather
than a list. `everyShippedSoundFileIsAccountedForAndEveryCreditIsReal` walks `ZenTomato/Resources`
**recursively**, matches six audio extensions rather than the one in use, and requires every file it
finds to be an `AlertSound` case with a non-empty author, a non-empty licence and an `https://`
source — or to be named in `soundsWeMadeOurselves`, which today holds exactly `Silence.caf` and a
reason. It also runs backwards: a credit naming a file that is not in the tree fails, because that is
a false statement about somebody's work rather than a missing one.

*Does a sound added later fail the build if nobody attributes it?* **Yes**, and the test's own comment
says it was demonstrated rather than argued: two files were planted, `Resources/Sub/Hidden.caf` and
`Resources/Uncredited.aiff`, and the suite was watched to fail. Its two predecessors could not see
either — the first compared two `switch` statements in the same file, the second read one directory
for one extension.

**This changes what F11 is.** It is not *build the attribution*. It is **move a list that is already
true onto a better surface without making it false on the way**, and that is a narrower job with a
sharper failure mode.

## The validate-every-artefact problem, stated precisely, because it is the whole risk

The validate-every-artefact rule in `docs/conventions.md` says a feature can judge its main output rigorously and still emit a **secondary artefact
nothing checks**. The instruction at this gate was to treat the attribution block as that artefact.
Having read the tree, the secondary artefact is somewhere slightly different, and naming it wrongly
would have built the fence in the wrong place.

**Today, `AlertSound.credits` is not a model of the artefact. It *is* the artefact.**
`SettingsView.swift:446` renders that exact `String?` into a section footer, unmodified — via
`footer(_:)`, which sets a font and a colour and touches no character. So
`theCreditsOnScreenMatchTheSoundsThatShip` asserting against `AlertSound.credits` is legitimate: it is
reading the output where it leaves the system.

**F11 is the change that breaks that.** An About screen wants each source to be a **tappable link**,
not a URL sitting inside a paragraph — and the moment the screen composes its own rows from
`AlertSound.attribution`, the string the test reads is no longer the thing on the screen. The test
would keep passing while rendering nothing, and it would be the exact failure `conventions.md`
records five times: *an assertion that re-derives its expected value cannot see the path that produces
the real one.*

**So the ruling this plan proposes: the screen renders from one content model, and the fence asserts
against that same model, and nothing about the credits is written twice.** Concretely — a small
`AboutContent` type that holds every string and every `URL` the screen shows, assembled from
`AppLicence` and `AlertSound` and from nowhere else; `AboutView` consumes it and adds no literal of
its own; the fence reads `AboutContent` and a second fence reads `AboutView.swift`'s source to prove
it holds no credit text, no author name and no `https://` literal.

That second fence is the one that carries the weight. A model-only assertion is satisfiable by a view
that ignores the model, which is precisely how the download-button defect in `conventions.md` survived
two fixes.

**One concrete trap this will hit, named now so it is not debugged later.**
`theCreditsOnScreenMatchTheSoundsThatShip` ends with

> `#expect(text.components(separatedBy: "https://").count - 1 == borrowed.count)`

— a link count over the whole blob. On the About screen that blob also contains
`https://www.gnu.org/licenses/gpl-3.0.html`, which is inside `AppLicence.notice`, and
`AppLicence.sourceURL`. Counted naively, the assertion fails for a screen that is entirely correct,
and the tempting fix is to relax it to `>=`, which would delete the only assertion that says *no
credit went missing*. The count must be taken over the credits region alone. This is the kind of
detail that gets fixed at 5pm by weakening the test.

**Three further checks, because "no delta" is a claim about the contract and claims get checked:**

1. **`SPEC.md`'s out-of-scope list does not name it.** That list is standalone watchOS · macOS ·

2. **`SPEC.md` line 30's *"Nothing else."*** governs **timer customization** — the six values the
   timer runs on. About is not a seventh value. It stores nothing, snapshots nothing, and cannot be
   changed. The precedent is already on the screen: the Version row lives in an About section

3. **`PolishFenceTests` must stay green untouched.** `noNewStoredShape` and `noNewPersistentSurface`
   are the relevant two, and F11 adds no stored shape and no persistence. `nothingFromTheParkedList`

   and this feature reaches for none of them. If any of those three needs an edit to accommodate this
   screen, **that is the signal to stop and come back to the gate**, not to edit the fence.

**Where the disagreement actually is, it is about a standing rule rather than the spec**, and it is in
the open questions below.

## The standing rules, confirmed one at a time

Required, and not treated as a formality — three of these are live on this screen specifically.

- **No capture surface.** The About screen accepts no input of any kind. No text field, no note, no
  "send feedback" box. This matters more here than it looks: a feedback field is the single most
  natural thing to put on an About screen, it is a capture surface, and it is forbidden for ever.
  `NoCaptureSurfaceTests` stands; `SettingsView.swift`'s own doc comment already states the
  prohibition and the new file will carry it too.
- **Todoist writes are complete-task only.** F11 touches no Todoist code path. `scripts/check-todoist-writes.sh`
  runs unchanged in `make ci`.
- **Todoist owns the hierarchy.** No model of any kind is added.
- **Local only, no analytics.** Nothing is reported, counted or sent. **The app itself makes no
  network request from this screen** — see Question 3, which is about what `openURL` hands to Safari.
- **Secrets never enter the tree.** No configuration, no key, no identifier. `make check-secrets` runs
  unchanged.
- **The agent never edits `docs/specs/SPEC.md`.** Nothing in this plan proposes an edit to it. The one
  documentation correction on the table is to `docs/chores/C18.md`, a chore record, and it is asked
  for rather than taken — Question 4.

### Foundational — no user-visible change

Both tasks below ship nothing a person can see. Labelled honestly, and the label is what stops the
group growing: everything that is not "assemble the content" or "fence the content" belongs to a
slice.

#### `F11-T1` — `AboutContent` · owner: **agent**

One value type holding what the screen shows: the licence notice, the pledge, the source `URL`, the
version string, and an ordered list of sound credits, each with a display name, an author, a licence
and a **parsed `URL`** rather than a `String`.

**The build is handed in, not read.** *(Corrected at adversarial review.)* The first draft of this
task had `AboutContent` read `AppBuild.current.described` for itself. `AppBuild.swift`'s own doc
comment forbids exactly that — *"the value is **handed in** at every call site. `current` reads the
bundle exactly once, in the app; tests pass a fixed value and the page stays deterministic."* A
content type that reaches into `Bundle.main` gives the fence nothing to assert but non-emptiness,
which is the tautology-with-a-green-tick `conventions.md` names. So `AboutContent` takes an
`AppBuild`; `AboutView`'s route passes `.current`, as the Version row already does at
`SettingsView.swift:432`, and the test passes a fixed one and asserts the exact string.

**Assembled from `AppLicence` and `AlertSound` and from nowhere else.** No second copy of the notice,
no re-typed author name. The value of doing this before any view exists is that the content becomes
testable without a rendered pixel — this project has no UI test target, and `SettingsLockTests`
already explains why its fences read source rather than pixels.

**Built from `AlertSound.playable`, never `allCases`**, for the reason `AlertSound.credits` already
gives: a sound whose file is not in the target is never played, so naming its author would claim we
used their work when we did not. Inheriting that decision rather than re-making it is the point of
assembling from the existing type.

**The `URL` is parsed here rather than at the point of display**, so an unparseable source becomes a
test failure in a foundational task instead of a link that silently does nothing on a phone.
`AlertSound.Attribution.source` is a `String`, so somebody has to parse it somewhere; doing it once,
early, is the difference between a failing test and a dead link. **Unverified** *(flagged at
adversarial review)*: the first draft asserted that "a `Text` containing a malformed URL renders
perfectly and is dead to the touch." That is a claim about SwiftUI nobody has run. What is checkable
without it is enough — `URL(string:)` returning `nil` is the failure, and the fence sees it.

*Checkpoint:* a test constructs `AboutContent` with a **fixed `AppBuild`** and asserts it carries the
GPL notice, the pledge, a `github.com` source URL, that exact version string, and exactly two sound
credits whose authors are `15HVojta_Michael` and `fmiramar_` and whose links resolve to the two
Freesound pages in `docs/sounds/candidates.md`. The existing suite passes unchanged, and its count
rises by the number of tests added — recorded, because a suite that shrinks is blind rather than
clean.

**Two credits is assertable, and here is why it is not a guess** *(checked at adversarial review,
because a count is the whole strength of this checkpoint)*. `AlertSound.playable` filters on
`Bundle.main.url(forResource:)`, and a test bundle's `Bundle.main` is ordinarily the test runner
rather than the app. It is not here: `project.yml:376` sets
`TEST_HOST: $(BUILT_PRODUCTS_DIR)/ZenTomato.app/…/ZenTomato`, so the tests run **inside the app** and
`playable` resolves both bells. **This is load-bearing and belongs in the fence's doc comment**, so
the next reader does not have to re-derive it — and if the test target is ever un-hosted, the
`AboutContent` count fence is the thing that should fail loudly.

**Do not copy `theCreditsOnScreenMatchTheSoundsThatShip`'s empty-list guard into the new fence.** That
test opens `guard borrowed.isEmpty == false else { … return }`, which is correct where it sits — it is
asserting that a heading never stands over an empty list. Copied into `AboutFenceTests` it becomes an
escape hatch: a mutation that empties the credits would take the early return and the suite would go
green on a screen with no credits on it. The new fence asserts **exactly two**, with no branch.

#### `F11-T2` — The fence, and the mutations · owner: **agent**

**The point of the task, not a garnish.** `AboutFenceTests`, in the shape `LicenceFenceTests` and
`PolishFenceTests` already take:

1. **The licence notice reaches the content.** `LicenceFenceTests.theGplNoticeShipsInsideTheApp`
   proves the constant exists; **nothing today proves it reaches a surface**, and that gap is the
   whole reason `D31` said this feature still had work in it.
2. **Every playable borrowed sound appears exactly once**, with author, licence and a followable
   `https` link — counted over the credits region, not the whole screen. See the trap named above.
3. **No credit is written twice.** Exactly one place in shipped Swift renders the credits.
4. **The view holds no literal of its own.** A source-tree assertion over `AboutView.swift`: no
   author name, no `freesound.org`, no `https://` literal, no fragment of the notice. This is what
   makes assertion (1) mean anything — a model-only fence is satisfied by a view that ignores the
   model.

**Retarget rather than duplicate.** `AlertSoundTests.theCreditsOnScreenMatchTheSoundsThatShip` exists
and is correct today. Once About is the surface, it must read what About renders or be replaced by
the fence above. **Two tests both claiming to be "the credits on screen", one of them reading a
surface that no longer carries them, is worse than one** — it is a green tick over a deleted feature,
and it is how `conventions.md`'s per-theme assertion ended up checking one theme.

*Checkpoint:* every mutation in the table below is **applied to the shipped code and the named test
is watched to fail**, with the pass count recorded at the moment of failure. `caught at 531/532` is
evidence; *prevented by construction* is an argument.

### Vertical slices — each one a thing you can hold

#### `F11-T3` — The screen, reached from Settings · owner: **agent**

`AboutView`, pushed by a `NavigationLink` from the existing About section of `SettingsView` — the
section that today holds only the Version row. The row's destination is a small wrapper view rather
than an inline closure, for the reason `TodoistSignInRoute` already documents in that file: a
destination written inline in a `NavigationLink` is rebuilt every time the parent's body runs, and
this parent reads the running timer.

**It obeys the design system with no exception.** Zero hardcoded colours, roles only —
SwiftLint's *"Palette outside the token layer"* rule fails the build on a raw `Palette.` step, and
`Typography` and `Color(.textMuted)` are what the existing headers and footers use. The screen is
long prose, so Dynamic Type at AX5 is a real case rather than a courtesy; the existing previews in
`SettingsView.swift` establish the convention, including the `.preferredColorScheme(.light)` that
`O35` records one preview as missing.

**It reports and does not accept.** No field, no toggle, no button that changes anything. The only
interactive elements are links out.

*Checkpoint:* on the simulator, open Settings, tap About, and read the GPL notice, the App Store
pledge, the version, and both bells with author and licence — in the default type size and at AX5,
in light and dark.

#### `F11-T4` — The links go somewhere, and the credits live in one place · owner: **agent**

Two halves of one indivisible move, which is why they are one task: the credits arrive on About and
**leave** `SettingsView`'s footer in the same commit. Splitting them produces either a period where
the same list is in two places and can drift, or one where it is in neither.

Links open through `@Environment(\.openURL)`, the mechanism `AlarmPermissionView` and
`MusicPickerView` already use. **This is the first time the app sends somebody to a third-party site**
— see Question 3.

**`D24`'s standard is the acceptance condition:** *"a list nobody can reach is not attribution."* After
this task the list is one tap further away than it is today and one tap from being **checkable**,
which is the property the ruling actually asked for. If the owner judges that a footer under the
picker is the more reachable place, that is Question 2 and the answer changes this task.

*Checkpoint:* on the simulator, tap the source link and land on the repository; tap each bell's link
and land on its Freesound page; return to Settings and confirm the sound picker's footer no longer
repeats the credits, and that the fence forbidding a second copy is the thing keeping it that way.

#### `F11-T5` — Read it on the phone · owner: **human**

`SPEC.md`'s standard: a *Done when* is closed on hardware, by the owner, with a build number and their
own words. Not an assertion.

Install the build. Open About. Answer four things: **is the licence notice readable, or is it a wall**
· does the source link open the repository · does a sound credit's link open the right sound · and,
with a block running, does the screen behave the way Question 1 was answered.

*Checkpoint:* recorded as an `O<n>` in `docs/plans/00-register.md` and closed by the owner with the
build number.

## Scope fence

Not in F11. Each needs its own gate.

- **The full GPL text in the app.** This is the one most likely to be asked for mid-build, because
  once a licence screen exists it feels like a paste. It is refused for a reason already written down:
  `AppLicence`'s own doc comment records that the GPL runs to thousands of words, so the app shows the
  **notice** and links the full text at the source — *the arrangement the GPL's own "How to Apply
  These Terms" appendix describes.* Reversing that would put the whole GPL into the binary, into every
  future diff, and into a screen nobody scrolls. *(The first draft said "5,600 words". Nobody counted;
  `AppLicence` says "thousands" and that is as far as this plan is entitled to go.)* The obligation is
  met; the paste is not.
- **An in-app changelog or "what's new".** The runner-up for mid-build creep, and it is a second
  document with a maintenance schedule attached.
- **Acknowledgements for anything that is not a sound** — fonts, icons, third-party code. There is no
  third-party code; `CLAUDE.md` forbids a dependency without a delta. When one exists, its credit is
  part of *its* gate.
- **A feedback, support or "rate this app" row.** A feedback field is a capture surface and is
  forbidden for ever, not deferred.
- **A privacy-policy screen.** `PrivacyManifestTests` covers the manifest the store requires; a
  human-readable policy screen is a different artefact and belongs to whatever gate ships the store
  listing.
- **A diagnostics or log-export row.** Adjacent to About on every other app and out of scope on this
  one: the export is `F6`'s, from the stats screen, and pointed at the Rhodia review.
- **Any visual treatment beyond the existing token system.** `F15` is the graphics pass and `F12` is
  themes; About is a customer of both and an author of neither.

## Open questions for the gate

Batched. Each changes what gets built, none is answered anywhere I can read, and none can be settled
by investigation.

**1. Does the About row stay live while a block is running?**
`D27` locks the customization rows and nothing else — `SettingsForm`'s `.disabled(isBlockRunning)`
sits on the `Group` holding block lengths, sprint and when-a-block-ends, and the About section is
deliberately outside it, as `SettingsLockTests.musicAndTodoistAreNotLocked` asserts for music and
Todoist. **My reading: leave it live.** Reading a licence changes nothing, and locking a read-only
screen would be a new rule rather than an application of an existing one. The reason to ask is that it
is a *new push onto the navigation stack from a sheet that is open during a running block*, and this
project has been bitten by that shape before. If the answer is "live", `SettingsLockTests` gains About
by name so the next reader does not have to infer it.

**2. Do the credits leave Settings, or appear in both places?**
`C18-T4` says *"when this screen is built the credits move to it."* `D24` says *"a list nobody can
reach is not attribution."* Those agree if About counts as reachable, and disagree if the owner's
ruling meant *on the same screen as the picker*. **My reading: move them**, one surface, fenced against
a second copy — a list in two places is a list that will drift, and the drift will be silent because
both copies read the same data until one of them stops. But this is a reduction in visibility of a
credit the owner ruled strictly on, and reducing it is the owner's call, not mine.

**3. The standing rule and the obligation point in opposite directions, and I would like this on the
record rather than resolved quietly.**
The rule is *no network except Todoist and MusicKit*. `D24` requires each credit to carry a **link**,
because *"the link is what makes the credit checkable rather than decorative"*. Tapping one hands a
URL to `openURL`; Safari then talks to `freesound.org` and `github.com`. **The case that this is no
violation:** the app issues no request, the traffic is Safari's, it happens only on a deliberate tap,
and the app already calls `openURL` in `AlarmPermissionView` and `MusicPickerView`. **The case that it
deserves a decision anyway:** both existing uses go to Apple's own Settings, and this is the first time
ZenPom sends its user to a third-party site — a rule read as *"this app causes no traffic to anyone
but Todoist and Apple"* is a defensible reading that this feature breaks. **I would build it with
links**, because a credit nobody can check is the decorative kind `D24` refused, and because the
