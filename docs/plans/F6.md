# F6 — Stats and export

**Gate:** requires F4 merged, your yes, and ratification of **D4**'s export shape (below).
**Branch:** `F6/stats-export`
**Spec:** Counts per task, project, day; I/E per task, day; Markdown export. *Done when:* the export of
one real study day is readable in the Rhodia without translation.

## Summary

Everything F2 through F5 recorded, read back. No new capture, no new models — F6 is queries and one
string.

The *Done when* is the most unusual acceptance criterion in the spec and it is the one that matters:
**readable in the Rhodia without translation.** Not "the export is valid Markdown." The test is whether
you can put the page next to a paper notebook during a two-week review and read it straight across
without decoding anything. That rules out IDs, ISO timestamps with timezone offsets, JSON-ish nesting,
and any column that exists because it was easy to compute. Every line has to earn its place by being
something you would actually read aloud to yourself.

## Counting rules

Stated up front because they are the kind of thing that silently differs between the stats screen and
the export, and then the numbers disagree and nobody knows which is right.

- **A day** is the local calendar day of the block's **start**. A pomodoro beginning 23:50 and ending
  00:15 belongs entirely to the day it started. One rule, applied everywhere, no split attribution.
- **A pomodoro counts** when it completed. Abandoned blocks (`wasAbandoned == true`) are excluded from
  counts and shown separately, if at all — a sprint you bailed on is not four pomodoros.
- **Breaks are not counted.** They are not pomodoros.
- **A distraction belongs** to the work block it was tapped in, and through it to that block's task and
  project.
- **A completion belongs** to the day it was recorded (D11), independently of any pomodoro. Completing
  a task is not a pomodoro and is never counted as one.
- **Task and project names come from the snapshot** on the row, never resolved live from the cache.
  This is why F5 and F3 store them: a two-week-old review shows what was true then. It also means a
  task deleted in Todoist still appears in your history, which is correct.
- **Rows with no task** — everything captured before F3 merged, plus any pomodoro attached to a project
  rather than a task — are grouped under the project, or under "No task" where there is not even that.
  Rendered plainly, not as an error state.

Implemented once, in a `StatsQuery` type. The stats screen and the exporter both call it. They cannot
disagree because there is only one of them.

## Tasks

### F6-T1 — Queries

`StatsQuery` over `PomodoroSession` and `Distraction`: totals by day, by project, by task, and I/E
counts by task and by day, for a given date range. `#Predicate`-based SwiftData fetches with the date
range pushed into the predicate rather than filtering in memory.

### F6-T2 — Stats screen

Three sections, each a plain list: **Days**, **Projects**, **Tasks**. Counts and I/E per row. Tapping a
day shows that day's distraction sentences.

No charts. No streaks, no badges, no trend lines — `SPEC.md` puts gamification in the out-of-scope list
explicitly, and a "you're on a 6-day streak" banner is exactly the thing it is ruling out. The screen's
job is to let you check a number before the export does the real work.

### F6-T3 — Export

Default range: **the trailing 14 days**, matching the Rhodia cadence, with a range picker to override.
`ShareLink` handing out a real `.md` file — named `ZenTomato-2026-08-08-to-2026-08-21.md`, so a file
sitting in Files a month later still says what it is.

```markdown
# ZenTomato — 2026-08-08 to 2026-08-21

42 pomodoros · 17 hours 30 minutes · 23 distractions (14 internal / 9 external)

## Days

| Date         | Pomodoros | I | E |
|--------------|-----------|---|---|
| Wed 19 Aug   | 6         | 3 | 1 |
| Thu 20 Aug   | 4         | 2 | 2 |

## Projects

- **Thesis** — 14 pomodoros (I 7 / E 2)
  - Ch.3 draft — 9
  - Reading — 5
- **Admin** — 3 pomodoros (I 1 / E 0)

## Distractions

### Ch.3 draft
- Wed 19 Aug, 14:32 — **I** — kept re-reading the same paragraph
- Wed 19 Aug, 14:41 — **E** — roommate came in
- Thu 20 Aug, 09:12 — **I** — *(no note)*
```

Deliberate choices, each aimed at the Rhodia test:

- **Dates read as "Wed 19 Aug", times as "14:32".** No ISO 8601, no timezone offsets, no seconds.
- **The summary line comes first**, so the top of the page answers "how did the fortnight go."
- **Distractions are grouped by task, not by day**, and this is the one real editorial decision in the
  feature. Chronological order tells you when you got distracted; by-task tells you *what* keeps
  distracting you — which is the self-knowledge the spec says the log exists for. The Days table
  already carries the chronology.
- **Skipped notes render as *(no note)***, not as a blank. A tap with no sentence is data; an empty line
  looks like a bug.
- **No IDs anywhere.** Not the Todoist ID, not the UUID, not the session ID.
- Empty range ⇒ a short "no pomodoros in this range" document rather than a skeleton of empty tables.

### F6-T4 — Export is a pure function

`makeMarkdown(from:range:) -> String`, taking already-fetched data and returning a string. No store
access, no I/O, no date-formatting from the ambient locale. That makes the whole export testable as a
golden file, which is the strongest evidence available for a feature whose acceptance criterion is
"readable."

## Tests

| Test | Asserts |
|---|---|
| `goldenExport` | fixture fortnight ⇒ byte-identical to a committed `.md`; diffs are visible in review |
| `dayBoundaryUsesStart` | 23:50→00:15 block counts on the starting day, once |
| `abandonedExcluded` | `wasAbandoned` rows absent from every count |
| `breaksNotCounted` | break sessions never appear as pomodoros |
| `snapshotNamesUsed` | task renamed after the fact ⇒ export shows the old name |
| `noTaskRowsGroupUnderProject` | pre-F3 and project-attached rows render, do not vanish |
| `skippedNoteRendersMarker` | `nil` note ⇒ *(no note)* |
| `emptyRangeIsReadable` | no data ⇒ one clear sentence, not empty tables |
| `defaultRangeIsTrailing14Days` | picker default |
| `statsScreenMatchesExport` | both call `StatsQuery`; totals identical on the same fixture |
| `noIdentifiersInOutput` | export contains no UUID and no Todoist ID |

The golden file is the centrepiece: it turns "is this readable" into a diff a human reviews once and a
machine defends forever.

## Device check

**Not gated on C4** — this one needs data, not a device. Export one real study day (or fortnight) and
read it next to the Rhodia. If any line needs translating, that is a finding and the format changes.
Paste the actual exported Markdown into the PR; it is the evidence.

## Evidence for the PR

`xcodebuild test`, `swiftlint --strict`, the golden file diff, and one real day's exported Markdown
pasted verbatim.

## Risks

- **Readability is subjective and you are the only judge.** Expect one or two format revisions after you
  see real data. The golden-file test makes those revisions cheap and visible; that is why it exists.
- **Scope pressure, the worst of the project.** A stats screen invites charts, streaks, weekly
  comparisons, "best day" — all named or implied in the out-of-scope list. F6's adversarial review
  should be read with that specifically in mind.
- **Large ranges** — an all-time export after months of use produces a long document. The 14-day default
  is the mitigation; no pagination is built.
